# X-02a — pose_cnn 코어 배선 및 실물 Encoder 통합

2026-09-26. **구현·기능 검증 완료, 검수 대기.** 기본 실행 6 case, 실제 Encoder 완주 6회, 정상 INFER 4회.
기존 20 TB 회귀 통과. core 자체는 FC 모형을 포함하므로 합성 대상이 아니다.
Encoder 100 MHz WNS −3.641 ns는 그대로이며 이번 단계에서 고치지 않았다.

## 3. 구현 전 명세 보정

1. **WR 오류는 ERR_DRAIN에 가지 않는다.** D08/T-07 그대로 마지막 B 응답 이후 error 5를 기록하고 FINISH로 직행한다.
   W6의 '각 경우 ERR_DRAIN 경유'를 read 세 위치에 한정했다.
2. 기존 FC 모형의 fixed pose로는 W7 입력 변화가 검증되지 않는다. 기본 모드는 유지하고 신규 core TB에서만
   RAM 읽기 모드를 켜 **실제 feature 384 word의 192-bit digest**를 pose 선으로 보낸다.
   이는 배선 검사용 값이다. 실제 FC 계산·pose 정확도·golden 추론은 검사하지 않았다.
3. `tb_top_infer`도 FC 모형을 사용하므로 포트 연결 보정을 추가 승인받았다.
4. 코어 내부 실물은 3개, FC 모형은 1개다. 실물 M00는 코어 밖에 연결한다.

자세한 checker 구성과 모형 가정은 [검증 설계](X-02a_검증_설계.md)를 참조한다.

## 4. W2 LOAD 및 W3 INFER 실측

실제 blob은 `wifi-csi-pose-main/HLS/pl_accel_v6/pl_accel_v6_weights.bin`, **422,992 B**.
SHA-256 `063d01b880c4d96f1fe61450a72a9911b222ebf67bbbbf560da700a7350b94bb`.
DDR BASE=0x10000000, INPUT=0x20000000, OUTPUT=0x30000000.
메모리 모형은 기본 지연 0 조건이다. 실제 보드 DDR 지연 실측이 아니다.

| 항목 | 관측 |
|---|---|
| 정상 LOAD | **10,114 cycle**, AR **47+187=234**, cfg_ok=1, done=1, error=0 |
| Loader 단독 대비 | 9,772 → 10,114, **+342 cycle**. M00의 명령/burst 연결 공백과 Top 전이를 포함한 전체 시간 차이 |
| output_scale_bits | **0x3BD997A8**, blob word 4와 동일 |
| 입력 | **1,440 word** 주소/값 전량 일치, AR **90** |
| 실물 Encoder | 수락 START→완료 **1,278,889 cycle**, E-01과 동일 |
| FC1 | FIFO push/pop **49,152 word** 전량 blob과 일치, AR **3,073** |
| 출력 | AW **1**, W 수락 **3**, DDR **24 byte 전량 일치**, 앞뒤 guard 미기록 |
| 정상 INFER 전체 | **1,338,265 cycle**, 정상 네 실행 모두 동일 |

FC1 주소는 BASE+5,936이다. BASE 자체가 정렬돼도 이 주소는 128 B 정렬이 아니어서
4 KiB 경계 분할이 생긴다. 그래서 정렬 기준선 3,072와 달리 실제 burst는 **3,073**이다.
LOAD +342는 Loader 처리 대기와 M00 전송 공백이 겹친 뒤의 순증분이다. 각 burst 지연을 단순 합산한 값이 아니다.

100 MHz로 환산한 INFER 시간은 **13.38265 ms**다. Encoder의 실제 timing closure가 되지 않았으므로
보드 실행 가능 시간으로 보증하지 않는다. 실제 FC 연산도 아직 포함하지 않는다.
이전 stub 전체 1,335,832 대비 +2,433 cycle이며, 이번 RAM 전량 읽기를 위해 core TB의 FC2/3 지연을
3/4에서 **2,052/388**로 늘린 차이(+2,049/+384)와 같다. 실제 FC 처리율을 뜻하지 않는다. 이전 fixture는 FC1 3,072 burst 및 Encoder stub을 사용하므로, 총 cycle 차이를 실물 Encoder의 성능 변화로 해석하지 않는다.

## 5. W4 D09 및 W5 Flatten

RAM 여섯 논리 출력은 상승 에지 직전 주소/선택에 해당하는 blob 값을 직후 출력하는지 비교했다.
정상 INFER마다 **8,029,596회(1,338,266개 에지 × 6출력)** 대조한다.
비유효 idle 주소의 X 응답도 그대로 비교하되, 정수 주소 0으로 해석하지 않는다.
유효 requant/GELU 요청에는 주소 X를 금지하고 최종 384 feature 모두 알려진 값임을 검사한다.

| 입력/실행 | Encoder 종료 잔값 Param/LUT | FC 종료 잔값 Param/LUT | FC 구간의 서로 다른 데이터 선택 검증 Param/LUT |
|---|---|---|---|
| 결정적 첫 실행 | **32 / 423** | **327 / 1023** | 57,747 / 57,746 cycle |
| 같은 입력 두 번째 | **32 / 423** | **327 / 1023** | 57,747 / 57,746 cycle |
| 난수 입력 | **32 / 424** | **327 / 1023** | 57,747 / 57,746 cycle |

다음 Encoder 실행에서는 남아 있는 FC 주소와 선택 데이터가 다른 cycle을 세었다.
같은 입력 재실행에서 Param **1,278,889**, LUT **1,028,756 cycle** 동안 실제 Encoder 값이 선택됐다.
단순히 두 주소가 다르기만 한 검사가 아니라, 두 주소의 데이터까지 다른 상황에서 출력이 맞는지 확인했다.
선택은 ENC=0, FC1~3=1이며 fc_start와 단계 전환도 함께 검사한다.

FC 모형은 각 단계의 Param 128/128/24, LUT 256/256, FCW 2,048/384개를 모두 읽어 스스로 검사한다.
Flat 0~383은 Pool의 **쓰기 버스에서 독립 수집한** 결과와 384 word 전량 대조한다.
주소·데이터 직결은 매 cycle 검사한다. 범위 밖 384~511에는 요청하지 않는다.

## 6. W7 같은 입력 재현 및 입력 변화

reset 없이 LOAD → INFER → INFER → 입력 변경 INFER를 실행했다.
결정적 입력의 식은 E-01과 같고, 변경 입력은 xorshift32 seed **0x6e01cafe**다.

| 입력 | 첫 실행 대비 feature 변화 | 시험용 192-bit digest |
|---|---:|---|
| 결정적 첫 실행 | 기준 | `d740b1dcc5777eb6ed2c49081c9280f2a45f75f43c1a738f` |
| 같은 입력 두 번째 | **0 / 384 word** | 동일 |
| 난수 입력 | **384 / 384 word** | `967591aa6a0b5a2586d9563474f1f79af3057bfb95d33d88` |

모형의 digest가 변했다는 점과 별개로 실제 Encoder feature 전량의 변화를 검사했다.
따라서 고정 출력만으로 공허하게 통과하지 않는다. 이 digest는 학습된 FC의 pose가 아니다.

## 7. W6 오류 경로와 공통 reset 복구

세 read 오류는 대상 첫 burst의 beat 7에 RRESP=SLVERR를 넣었다.
write는 BRESP=SLVERR다. 아래는 실제 PASS 출력이다.

```text
PASS: X-02a W6 case=1 error=4 cfg=0 cycles=860 ERR_DRAIN_cycles=826 enc_starts=0 input_writes=0 FC1_pushes=0 write_beats=0 rd_busy=0 wr_busy=0
PASS: X-02a W6 case=2 error=4 cfg=1 cycles=1623 ERR_DRAIN_cycles=1610 enc_starts=0 input_writes=8 FC1_pushes=0 write_beats=0 rd_busy=0 wr_busy=0
PASS: X-02a D08/D09 revoked_param_reads=117 revoked_lut_reads=245 FC_active=1 addresses_continue=1 selected_data_checker_continues=1
PASS: X-02a W6 case=3 error=4 cfg=1 cycles=1335811 ERR_DRAIN_cycles=55288 enc_starts=1 input_writes=1440 FC1_pushes=8 write_beats=0 rd_busy=0 wr_busy=0
PASS: X-02a W6 case=4 error=5 cfg=1 cycles=1338265 ERR_DRAIN_cycles=0 enc_starts=1 input_writes=1440 FC1_pushes=49152 write_beats=3 rd_busy=0 wr_busy=0
```

LOAD 실패는 cfg_ok=0. 입력 오류는 enc_start=0. FC1 오류에서는 다음 FC 시작을 내지 않고
모형 FC가 active에 남는 것을 확인했다. 이를 몰래 중단시키지 않는다.
WR 오류는 W 3개와 마지막 B 수락을 마친 뒤 error 5이며 ERR_DRAIN 체류가 **0 cycle**다.
각 case는 공통 reset으로 격리하고 재LOAD한다. 마지막 case 5에서 **reset→재LOAD→정상 재INFER**를 실행해 복구를 확인했다.
ERR_DRAIN에서는 FC가 active여도 공유 RAM 소유권을 잃는다. `ram_shared_owned`는
검사기만 유효 응답 여부를 판단하도록 하는 TB 변수이며 FC 동작/주소/done을 바꾸지 않는다.
비소유 Param/LUT 읽기를 별도로 세고, 코어 checker는 계속 실제 선택된 Encoder 값을 검사한다.
정상 INFER에서는 비소유 읽기 0건을 요구한다. 오류 이후의 FC 중간 결과는 폐기하며 reset이 필요하다.
실제 BD reset 범위의 안전성 검증을 대신하지 않는다. AXI/FC 프로토콜 위반 0, 모든 case 종료 시 quiescent.

## 8. W8 구성 블록 단독 합성

Vivado 2020.2 / xc7z020clg400-1 / 기존 100 MHz OOC 제약.
`pose_cnn`은 TB 전용 FC를 포함하므로 합성하지 않았다.

| 블록 | LUT | FF | RAMB36 / RAMB18 | DSP | 이전 → 현재 WNS | 래치/조합 루프 |
|---|---:|---:|---:|---:|---|---|
| ctrl | 455 | 225 | 0 / 0 | 0 | +1.741 → **+1.741 ns** | 0 / 0 |
| Loader | 650 | 212 | 10 / 3 | 0 | +1.365 → **+1.365 ns** | 0 / 0 |
| Encoder | 6,490 | 3,530 | 13 / 0 | 10 | −3.641 → **−3.641 ns 실패** | 0 / 0 |

자원·타이밍 모두 이전과 같다. Encoder 임계 경로는 `u_enc_rq/param3_reg[69]/C` → `u_enc_rq/rq_reg[*]/R`.
합성 wall-clock은 ctrl 51.837초, Loader 48.477초, Encoder 92.104초.
실행 전체에는 기존 Common 17-741 / Timing 38-242 / Vivado 12-180 경고가 있다.
시뮬레이션 compile/elaboration 경고 0과 구분한다. Encoder 타이밍은 이번 기능 통과 조건에 넣지 않았고 개선하지 않았다.

## 9. W9 회귀·실행 기록

기존 19종 + E-01 등가성 TB = **20종** 모두 실제 실행했다.
Top 4/상태·CSR 2/S00 4/M00 4/AXI 모형 1/Loader 4/Encoder 등가성 1.
기존 PASS/OBS **1,355줄이 E-01 실행 결과와 동일**하다.
세 legacy TB의 차이에서 새 포트 연결을 제거하면 원래 파일과 완전히 같다.
[기존 TB 변경 diff](X-02a_existing_tb_changes.diff).

신규 core TB는 기본 실행으로 6 case 전부 통과했다. 정상 INFER 4회, 실물 Encoder 완주 6회.
최종 xvlog **1.078초**, xvlog -sv **1.063초**, xelab **6.404초**,
core xsim **142.758초**. 별도 Encoder 등가성 회귀 xsim 89.609초.
최종 xvlog/xvlog -sv/xelab 오류·경고 0. runtime FAIL/Fatal 부재와 최종 PASS/finish를 함께 확인했다.
