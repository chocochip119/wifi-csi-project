# T-05 P9 보완 — 기존 INFER TB 최소 수정과 재검증

2026-09-25. **사용자의 최소 수정 승인 후 tb_top_infer 13조건·15회 전체 PASS. P9 해결.** 이번 추가 작업에서 변경한 소스는 `tb_top_infer.v` 한 개다. 기존 RTL과 다른 TB/stub는 변경하지 않았다. Claude 검수가 병행 중이므로 공통 문서와 기존 보고서를 덮어쓰지 않고 이 보완 기록을 별도로 작성했다.

이 기록은 [기존 T-05 보고서](T-05_구현_검증기록.md)의 **P9 실패·수정 허용 대기 상태를 대체**한다. 당시 실패 로그는 이력으로 유지한다. T-06은 시작하지 않았고, P7의 FC1 오류 후 reset·재LOAD 복구 시험은 이번 추가 실행에 포함하지 않았다.

## 변경 이유와 범위

기존 T-04 TB는 `fc_done=0`, FC 출력=0, ENC→FINISH를 전제로 했다. T-05의 ENC→FC1 동작을 반영하려면 입력 검사를 유지한 채 후속 FC1을 정상 완료시키는 연결이 필요했다. RTL을 force하거나 성공/오류 기대값을 완화하지 않았다.

| 변경 위치 | 최소 보완 내용 |
| --- | --- |
| [tb_top_infer.v](../testbench/tb_top_infer.v) 225행 | 기존 fc_stub 재사용. done/full의 0 고정을 제거하고 실제 FIFO push/pop 뒤 완료하도록 연결 |
| 232행, 389행 | FC1 read용 결정적 패턴 영역 추가. 이 TB는 기존처럼 cfg_ok를 직접 주는 입력 전용 fixture이므로 LOAD 없이 reset base=0, FC 주소=5,936을 사용한다. D06의 실제 LOAD 연결 검증은 tb_top_fc1에서 수행한 결과를 유지 |
| 287행, 322행 | LOAD/write 출력 0과 입력/Encoder 대기 중의 비활성 검사는 유지. Encoder 완료 cycle에 FC1 START/read 발행 및 FC1 진입만 허용 |
| 294행, 333행 | 입력 read 1회와 후속 FC1 read 1회를 구분. 기존 AR 범위·burst·R beat 관측은 입력 read만 집계 |
| 355행 | 입력 read 완료 시각을 FC1 read 완료가 덮어쓰지 않도록 입력 상태에서만 기록 |
| 396행, 492행 | 정상 전체 실행에 FC1 전송이 추가되어 bounded timeout만 확장(명령 30,000→300,000 cycle, 전체 5→20 ms) |
| 435행 | 성공 실행의 FC1 START 1회와 push/pop=49,152, FIFO empty·idle 확인. NO_CFG/입력 read 오류에서는 FC1 활동 0 확인 |

원래 13조건, 입력 1,440 word 전량 대조, 주소 유일성·순서, guard, stall, Encoder 지연/펄스/레벨, NO_CFG, 입력 read 오류 및 오류 후 재실행 검사는 유지했다. 입력 TB의 `commands`/`AR`/`R` 값은 입력 단계만 뜻하고 별도의 FC 통계 PASS 줄을 추가했다. FC1의 상세 데이터·D06·backpressure 검사는 기존 tb_top_fc1 결과를 재사용한다.

## Claude 검수 인계

- 이번 보완 직전의 rtl/tb **22파일 중 tb_top_infer 한 개만 변경**, 나머지 21파일 해시 동일. 기존 T-05 이후 추가 소스 수정은 이 TB뿐이다.
- RTL이 같으므로 합성과 기존 12개 회귀를 반복하지 않았다. 앞선 12개 PASS에 이번 tb_top_infer PASS가 추가되어 **누적 회귀 13종 통과**다. 이번에는 영향받은 TB 하나만 다시 실행했다.
- 실행 중 PROJECT_CONTEXT.md에 Claude 검수 결과가 추가된 것을 확인했다. P9 최소 보완은 이번 사용자 승인으로 이미 완료했으므로 다음 명세에서 중복 작업할 필요가 없다.
- 같은 문서에서 P7의 `공통 reset → 재LOAD → 재INFER` 인정 보정도 확인했다. **해당 복구 시험은 아직 수행하지 않았으며**, 현재 FC1 오류 뒤 단순 재START가 가능하다고 표시하지 않는다. 다음 작업/검수 범위와 함께 관리할 항목이다.
- 검수 중인 RTL·공통 문서 및 기존 보고서는 이 보완에서 편집하지 않았다. 본 기록과 diff가 최신 P9 결과다. Notion 및 팀 메시지는 전송하지 않았다.
