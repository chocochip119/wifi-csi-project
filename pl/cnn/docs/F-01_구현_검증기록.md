# F-01 구현·검증 기록 — FC 저장소 3종 완료

2026-09-26. 확정된 full-write 거부 계약에 따라 FC1 FIFO를 추가했다. hidden/pose RTL과 Y4/Y5 검사 본문은 그대로 보존했다. FC 연산·제어와 `fc_stub` 교체는 이번 범위에 포함하지 않았다.

## 1. 확정 계약과 구현

원문: `IP_v1_0/IP_v1_0/interface_spec/Pose_CNN_IP_Interface_Spec.xlsx`, `08_FC`.

| 근거 | 계약 | 구현 |
|---|---|---|
| r26 | FIFO 512×64 bit | `mem[0:511]`, 64-bit, 4,096 byte |
| r31~33 | we/data 쓰기, full이면 push 금지 | `push = fifo_we && !fifo_full`; full+pop 예외 없음 |
| r34 | `fifo_re && !fifo_empty`에서 pop | `pop = fifo_re && !fifo_empty` |
| r35~36 | FWFT, !empty이면 이미 유효한 head | 동기 BRAM 다음-head 읽기와 최초 word bypass |
| r95~99 | hidden byte 쓰기/64-bit 1-cycle 읽기 | 2×128 byte, 8 lane, read-first. 앞선 구현 무변경 |
| r16, r106~109 | pose 24 byte 병렬 출력, byte k 배치 | 192-bit 명시적 연결, 일부 쓰기 외 나머지 유지. 앞선 구현 무변경 |

이전 Y2의 “full에서 동시 push/pop 후 512개 유지”는 r33/Y3와 충돌했다. 사용자가 **full에서는 항상 write 거부**를 확정했다. full 미만이어도 empty이면 유효 pop이 없으므로, empty에서 we/re 동시 입력은 새 word 1개를 남긴다.

FIFO의 읽기·쓰기 포인터는 각각 9-bit로 0~511을 순환한다. 10-bit `count_reg`는 0~512를 표현한다. 판정식은 `fifo_full = (count_reg == 10'd512)`, `fifo_empty = (count_reg == 10'd0)`이다. 포인터·개수·head 선택 제어는 현재/다음값으로 분리했다. push만 수락되면 +1, pop만 수락되면 −1, 둘 다 수락되거나 둘 다 없으면 유지한다.

| edge 직전 | fifo_we / fifo_re | 수락 | edge 이후 |
|---|---|---|---|
| count=0 | 1 / 1 | push만 | count=1, 새 word가 head |
| count=511 | 1 / 1 | push+pop | count=511, 다음 head |
| count=512 | 1 / 1 | pop만 | count=511, write 데이터 유실 |
| count=512 | 1 / 0 | 둘 다 없음 | count=512, 기존 내용 보존 |

full-write 데이터 유실은 **Top이 막아야 하는 오용 계약**이다. RTL에 overflow 출력이나 full+pop 수락 예외를 추가하지 않았다.

### FWFT와 BRAM을 함께 만족시키는 구조

배열은 클록당 한 주소에만 쓴다. 현재 head는 출력에 이미 존재하며, 2개 이상 남아 있을 때 pop이 발생하면 **그 edge에서 다음 주소를 동기 읽기**한다. edge 뒤에는 다음 word가 바로 head가 된다. 빈 FIFO에 처음 쓰거나 1개 남은 상태에서 pop+push로 교체할 때는 입력 word를 bypass 레지스터에 보관하여 RAM 지연을 피한다. 이 경우 배열의 같은 주소 동시 read/write 결과에 의존하지 않는다.

BRAM 출력과 bypass는 배열 word의 사본이며 추가 FIFO 용량이 아니다. 정원은 항상 512개다. reset은 동기식 active-low이며 포인터·카운터·선택 제어만 초기화한다. 배열과 cached data는 reset하지 않는다. empty일 때 `fifo_rdata`는 유효하지 않다.

hidden은 명세가 요구한 5-bit read 주소·64-bit read 데이터를 그대로 유지한다. 별도 bank 입력을 사용하므로 bank 내부 byte 주소는 0~127, word 주소는 0~15다. 동일 주소를 같은 edge에 쓰고 읽으면 이전 byte를 반환한다. pose는 별도 동기 read 포트가 없어서 write edge 전에는 이전 병렬 출력, edge 후에는 새 병렬 출력이 보인다. hidden과 pose 저장 내용은 모두 reset으로 지우지 않는다.

## 3. Y1~Y7 관측값

| 항목 | 실제 관측 |
|---|---|
| Y1 기본 | 512 push → 512 pop 전량 순서 일치. 511개에서 !full, 512개에서 full, 배출 후 empty |
| Y1 FWFT | pop 전에 head 유효. pop 없이 8 cycle 유지. 매 step 전후 head 전량 대조 |
| Y2 full pop/rewrite | 512→511에서 full 해제, 다음 write 수락 후 512 |
| Y2 empty pop | 명시적 4회 read 시도에서 두 포인터 이동 0 |
| Y2 full 미만 동시 전송 | count=511 유지, 2,048 push/pop 연속, 9-bit 포인터 각 4바퀴. 남은 word 포함 2,559개 순서 일치 |
| Y2 full 동시 read/write | **512→511**, 고유 거부 word `DEAD_F011_BAD0_0001`; 이후 511회 pop에서 출현 0. 동시 pop까지 포함하여 기존 512 word 모두 보존 |
| Y3 full write 단독 | **512→512**, 고유 거부 word `DEAD_F011_BAD0_0002`; 이후 512회 pop에서 출현 0 |
| Y2 빈 경계 | empty에서 we/re 동시 입력은 0→1, count=1 교체 64회에서 FWFT 공백 없음 |
| Y2 난수 정체 | seed `F0015128`, 4,096 cycle, 합법 write/임의 read, 전량 대조 후 empty |
| Y1/Y2 reset | count=3에서 상승 edge 전 변화 없음, edge 후 count/포인터=0. 저장 내용 유지 및 reset 중 write 차단, 이후 새 push/pop 성공 |
| Y4/Y5 | **기존 215건·663 cycle 그대로**, 원래 PASS/OBS 7줄 동일 |
| Y6 | FIFO 포함 3종 각각 및 묶음 합성 성공, 래치/조합 루프 0 |
| Y7 | 기존 22 TB 무수정 재실행 통과. 이전 결과와 PASS/OBS/RESULT 1,402줄 동일 |

FIFO 전체 수락 push **6,189**, pop **6,186**, reset으로 버린 기존 word **3**. 의도적 full-write 거부 **2회**, 거부 word 재출현 **0**, full 미만 동시 수락 **3,115회**, empty read 무시 **55회**. FIFO 검증 기간은 **10,327 cycle**이다.

전체 기본 실행: **80,662 assertion / 10,990 cycle**, 불일치 0. FIFO를 제외한 앞부분의 Y4/Y5가 정확히 215건·663 cycle에서 끝나는지 TB가 직접 검사한다. Y4/Y5 입력 조건·기대값·검사 순서는 바꾸지 않았다. 보존 증거: `F-01_Y45_preservation.json`.

`xvlog`/`xvlog -sv`/`xelab` 오류·경고 **0**, runtime FAIL/Fatal **0**. exit code뿐 아니라 `PASS: tb_fc_storage ALL Y1-Y5 cases complete`와 `$finish`를 확인했다. 새 TB의 compile/elaboration/simulation은 각각 1.016/0.989/3.174/5.512초였다.

## 4. 합성 결과

Vivado 2020.2, `xc7z020clg400-1`, 기존 `syn_check.tcl`과 100 MHz `timing_100mhz.xdc` 사용. 입력/출력 delay 2 ns, OOC 결과다. `check_timing -verbose`, LUTLP-1 DRC 및 자원 상세도 확인했다.

| 대상 | LUT (중 LUTRAM) | FF | RAMB36 / RAMB18 | DSP | WNS | 래치 / 조합 루프 | wall-clock |
|---|---:|---:|---|---:|---|---|---|
| fc1_weight_fifo | 104 (0) | 93 | **1 / 0** | 0 | **+2.641 ns** | 0 / 0 | 50.517 s |
| hidden_buffer | 73 (64) | 64 | 0 / 0 | 0 | +5.501 ns | 0 / 0 | 58.834 s |
| pose_buffer | 25 (0) | 192 | 0 / 0 | 0 | +5.501 ns | 0 / 0 | 44.941 s |
| 3종 묶음 fc_storage_ooc | **170 (64)** | **349** | **1 / 0** | 0 | **+2.615 ns** | 0 / 0 | 52.762 s |

FIFO의 32,768-bit 배열은 `mem_reg RAMB36E1` **1개**로 추론됐다. 외부 FF 93개는 포인터 18 + count 10 + bypass 선택 1 + bypass data 64다. hidden은 RAM32M 16개, pose는 FF 192개다. 묶음의 LUT 170개는 실제 합성 최적화 결과이며 단독 합과 다르다. hidden/pose RTL은 무변경이므로 앞선 단독 결과를 유지했다.

FIFO 단독 임계 경로는 `mem_reg/CLKARDCLK` → `fifo_rdata[0]`, BRAM 출력과 LUT3 mux 한 단계이며 데이터 경로 지연 4.351 ns다. 묶음에서도 BRAM 출력→FIFO 데이터 출력 경로가 임계 경로다. 이 수치는 FC MAC 연결이나 P&R 타이밍 검증을 대신하지 않는다.

합성 오류 0. 기존 Common 17-741(Tcl store 접근), Timing 38-242(OOC clock skew), Vivado 12-180(빈 latch/memory 검색) 경고는 로그에 남겼다. 시뮬레이션 경고 0과 합성 환경 경고를 구분한다.

## 7. Notion 복사용 요약

F-01 완료. FC1 weight FIFO(512×64, FWFT), hidden(2×128 byte), pose(24 byte 병렬 출력) 저장소를 검증했다. FIFO는 full이면 write를 항상 버리며 동시 pop이면 512→511이다. 두 고유 거부 word가 이후 출력에 나타나지 않음을 전량 대조했다. 4바퀴 랩어라운드, 난수 정체, 동기 reset 후 재사용 통과. Y4/Y5는 기존 코드와 215건·663 cycle 관측값 그대로 유지. 전체 저장소 TB 80,662건 검사 통과, 기존 22 TB 무수정 통과. FIFO RAMB36 1개/LUT104/FF93/WNS +2.641 ns, 세 저장소 묶음 LUT170/FF349/RAMB36 1개/WNS +2.615 ns. 래치·조합 루프 0. 기존 RTL·참고 원본 무변경. FC 연산·제어와 core 연결은 아직 진행하지 않았다.
