# E-02a — post-route requant 구간별 지연

2026-09-26. RTL 변경 없이 Vivado 2020.2의 실제 배선 보고서와 배선 netlist를 대조했다.
아래 값은 **기본 directive, 10 ns OOC** 결과다. 단위는 ns.
성능 directive는 경로 시작점과 최악 블록도 바꾸므로, 이 표를 성능 실행의 경로라고 읽으면 안 된다.

## 경계 정의

실제 RTL은 `half = 1 << (shift-1)`를 만들고, `(acc ± half) >>> shift`를 계산한 뒤 포화한다.
따라서 산술 경로에서 **half/라운딩이 오른쪽 가변 shift보다 앞**이다.
명세의 ㄱ(Q→shift 진입)과 ㄷ(half 덧셈/뺄셈)은 서로 겹친다. 둘을 더하면 중복 계산이다.
합성된 LUT는 디코드·부호·mux를 합칠 수 있으므로 아래는 명시한 물리 핀 사이의 구간이며,
각 Verilog 연산자를 고립시켜 측정한 수치가 아니다. 임계 경로는 선택된 한 가지 arc다.
`<<<`와 `>>>`의 모든 분기 지연을 이 한 경로로 대표하지 않는다.

Encoder의 최악 시작점은 `param3_reg[68]`(shift[4])로 바뀌었다. FC는 `param3_reg[69]`(shift[5])다.

| 겹치지 않는 구간 | Encoder 구간 / 누적 | FC 구간 / 누적 |
|---|---:|---:|
| 발사 FF C→Q | 0.419 / 0.419 | 0.518 / 0.518 |
| Q→half 디코드 및 carry 입력 준비 | 1.899 / 2.318 | 1.869 / 2.387 |
| half 가감 carry chain | 2.486 / 4.804 | 2.328 / 4.715 |
| 오른쪽 가변 shift·부호 선택 mux | **4.329** / 9.133 | 3.234 / 7.949 |
| 포화 비교·출력/reset 선택→도착 FF | 3.821 / 12.954 | **3.856** / 11.805 |
| 전체 data path | **12.954** | **11.805** |

누적은 발사 FF의 C 도착 이후부터 센다. 보고서의 launch clock delay 0.973 ns(OOC 추정)는 제외하며 C→Q는 포함한다.
표의 합은 보고서의 Data Path Delay와 0.001 ns 해상도에서 일치한다.

명세 순서로 다시 쓰면 ㄱ Q→shift 진입 경계는 Encoder **4.385**, FC **4.197**이다.
ㄴ shift·부호 선택은 **4.329 / 3.234**, ㄷ carry 가감은 **2.486 / 2.328**,
ㄹ 포화 비교→FF 입력은 **3.821 / 3.856**이다. ㄱ에는 ㄷ과 half 디코드가 이미 들어 있다.

## 물리 핀과 원문 Path(ns)

| 경계 | Encoder 핀 (u_enc_rq/ 생략) | Path(ns) | FC 핀 (u_rq/ 생략) | Path(ns) |
|---|---|---:|---|---:|
| 발사 FF C | param3_reg[68]/C | 0.973 | param3_reg[69]/C | 0.973 |
| 발사 FF Q | param3_reg[68]/Q | 1.392 | param3_reg[69]/Q | 1.491 |
| 첫 가감 carry 입력 | rq_reg[3]_i_12/S[1] | 3.291 | rq_reg[7]_i_361/S[0] | 3.360 |
| 마지막 가감 carry 출력 | rq_reg[7]_i_115/O[3] | 5.777 | rq_reg[7]_i_133/O[3] | 5.688 |
| shift·부호 mux 출력 | rq[7]_i_721/O | 10.106 | rq_reg[7]_i_828/O | 8.922 |
| 도착 FF 동기 reset 핀 | rq_reg[2]/R | 13.927 | rq_reg[1]/R | 12.778 |

Encoder carry 22개는 가감 16개 + 비교 6개, FC carry 22개는 가감 15개 + 비교 7개다.
가감 carry에는 `ADDER_THRESHOLD`, 비교 carry에는 `COMPARATOR_THRESHOLD` 속성이 있고,
그 사이 mux 입력의 shift 비트와 acc 부호 연결을 netlist에서 확인했다.
LUT 이름만 보고 연산을 추측하지 않았다. `/R`는 FDRE의 **동기 reset 입력**이며
RTL 외부 reset 지연이라는 뜻이 아니다. 포화 비트가 이 핀으로 매핑된 경로다.

## 가상 경계 숫자 — 구현·재합성하지 않음

현재 경로를 같은 배선 지연 그대로 두 구간으로 나눈 산술값이다.
새 FF의 C→Q/setup, 새 배선·fanout, valid/tag 정렬, 다른 비트·다른 시작점은 계산에 포함하지 않았다.
따라서 다음 수치는 파이프라인을 실제로 넣었을 때의 WNS나 달성 주파수를 보장하지 않는다.

| 구성·가상 경계 | 앞부분 | 뒷부분 | 남는 긴 부분 |
|---|---:|---:|---:|
| Encoder: 가장 긴 shift 구간 직전(가감 carry 뒤) | 4.804 | 8.150 | **8.150** |
| FC: 가장 긴 포화 구간 직전(shift·부호 mux 뒤) | 7.949 | 3.856 | **7.949** |
| FC: 가감 carry 뒤(Encoder와 같은 산술 경계) | 4.715 | 7.090 | **7.090** |
| Encoder: shift·부호 mux 뒤 | 9.133 | 3.821 | **9.133** |

Encoder 성능 실행에는 Pool·Conv MAC의 다른 실패 경로도 남았다.
이 requant 경계 한 곳만 바꾸면 Encoder 전체가 통과한다는 판정은 하지 않는다.
