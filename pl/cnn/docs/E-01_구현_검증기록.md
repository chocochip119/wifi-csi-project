# E-01 — Encoder Buffer BRAM 변환과 원본 대조

2026-09-26. 승인 범위: Buffer 저장 구조, Buffer/Pool/gelu_stage의 timescale, 신규 등가성 TB, 검증 및 전달 자료.

**결과: 검증 후보의 기능 대조와 합성은 성공했다. 100 MHz 타이밍은 실패했다.**
현재 공유 `rtl/encoder`에는 외부에서 다시 복사한 원본이 있으므로, 동시 편집 종료 확인 전에는 덮어쓰지 않았다.
실제 검증한 후보는 [후보 ZIP](E-01_encoder_candidate.zip), [원본 대비 패치](E-01_encoder_patch.diff)에 보존했다.
공유 작업본 반영은 보류 상태이며, 반영 완료나 X-02 준비 완료로 표시하지 않는다.

## 1. 명세 검토 및 범위

- 원본 Verilog는 합성 대상 6개와 TB 3개로 총 9개다. 처음 9개를 복사한 직후 SHA-256을 기록했다.
  이후 다른 작업이 `rtl/encoder`를 합성 대상 6개만 둔 구성으로 다시 준비했다. 그 README와 원본 해시 문서는 보존했다.
  원본 폴더는 기타 스크립트/문서까지 **14개 전체 무변경**이다.
- `feat_raddr`는 9-bit지만 `Pool.v:140`의 실제 저장소는 `res_mem[0:383]`이다.
  따라서 0~511을 모두 검사하되 **384개 유효 word와 범위 밖 128개 X 응답을 구분**했다.
  512개 모두 유효 데이터라고 주장하지 않는다.
- 두 입력으로 하는 전 구간 시뮬레이션은 요청된 등가성 대조다. 모든 가능한 입력에 대한 형식 검증은 아니다.
  별도로 저장소 대응 불변식과 byte 순서/1-cycle/read-first 검사를 제시한다.
- 1,278,890이라는 기존 수치는 시작·완료 에지를 모두 포함한 관측 개수와 일치한다.
  수락 START에서 완료 수락까지 경과 주기는 **1,278,889**였다. 원본과 후보에서 정확히 같다.
- `CNN_Encoder.v`, `Conv_MAC.v`, `requant_stage.v`, 우리 RTL 및 기존 TB는 수정하지 않았다.
  명세의 `기존 18 TB`는 현재 실제 목록으로 **19개**이며 모두 실행했다.

## 2. 바뀐 회로와 등가성 근거

후보 `Buffer.v:23`부터 generate 분기를 둔다. W>R이고 폭 비율이 정확한 2의 거듭제곱이면
넓은 word 배열을 사용한다. 현 입력 버퍼는 **1,440 × 64-bit = 92,160 bit**다.

- `Buffer.v:36`: 쓰기 한 번에 `mem[waddr] <= wdata` 한 주소만 갱신한다.
- 같은 상승 에지에 `read_word_reg`와 `read_lane_reg`를 함께 등록한다.
- 등록된 lane으로 등록된 word를 조합 선택한다. 현재 `raddr` 하위 비트를 직접 쓰지 않는다.
- 예: `waddr=2`의 `wdata[7:0]`은 `raddr=16`, `[63:56]`은 `raddr=23`에 대응한다.
  주소를 바꾸기만 해서는 출력이 바뀌지 않고 다음 상승 에지 후에 바뀐다.
- 동시 같은 word 읽기/쓰기는 nonblocking 대입 때문에 **쓰기 전 값(read-first)**을 반환한다.
- RAM reset이나 초기화, 출력 지연 추가, 포트·폭 변경은 없다.
- W==R 및 W<R은 원본 순차문 그대로 `gen_legacy`에 남겼다. 정수 비율이지만 2의 거듭제곱이 아닌 24/8도 원본 경로다.
  원본 반복문을 보존했으며 신규 빠른 경로에는 for/task/function을 넣지 않았다.
- `Pool.v`/`gelu_stage.v`는 첫 줄의 `` `timescale 1ns / 1ps ``만 추가했다. byte 단위로 확인했다.

현재 64/8 구성에서 쓰기 후 항상 다음 관계가 성립한다.

```text
원본.byte_mem[8*w + b] = 후보.word_mem[w][8*b +: 8], b=0..7
```

읽기 주소 `r=8*w+b`의 word/lane을 같은 에지에 보관하므로 다음 출력은 원본의 같은 byte다.
같은 에지의 write는 양쪽에서 읽기 뒤에 반영된다. 이 불변식이 초기 미기록 메모리와 모든 합법적 쓰기에서 유지되므로,
현재 두 실제 인스턴스의 유효 주소 영역에 대해 저장 구조만 달라진다. 임의의 비정상 parameter/주소, gate-level collision,
배치·배선 후 동작까지 검증했다고 확대하지 않는다.

## 3. TB 구성 및 실제 입력

신규 [tb_encoder_equiv.v](../testbench/tb_encoder_equiv.v)는 원본과 후보 Encoder 두 개를 동시에 구동한다.
원본 6개는 scratch에 복사해 timescale과 모듈 식별자 `_e01_ref`만 바꿨다.
정규식 변환을 다시 계산하여 실제 참조 소스와 일치함을 확인했다. 원본 논리는 변경하지 않았다.

두 Encoder에 동일 clock/reset/start/입력 쓰기와 **실물 weight_param_loader의 같은 RAM 응답**을 준다.
원본의 RAM 요청 주소로 Loader를 구동하고, 후보의 모든 요청 주소를 매 cycle 비교한다.
따라서 주소 불일치를 공통 응답으로 가리는 경우에도 주소 검사에서 즉시 실패한다.

실제 blob:

```text
D:\2609_final_project\wifi-csi-pose-main\HLS\pl_accel_v6\pl_accel_v6_weights.bin
422,992 byte
SHA-256 063d01b880c4d96f1fe61450a72a9911b222ebf67bbbbf560da700a7350b94bb
LOAD 3,722 beat / 9,772 cycle / pool_mult=0x783b66b4 / pool_shift=31
```

입력은 각 11,520 byte다. case 0은 byte index i에 대해 `(i*37+(i/256)*11+19)&255`,
case 1은 xorshift32 seed **0x6e01cafe**의 하위 byte를 사용했다.

## 4. 전 구간 비교 관측

매 cycle 5개 외부 출력(`enc_done`, `conv_raddr`, `enc_param_raddr`, `enc_lut_raddr`, `feat_rdata`, 합계 93-bit)과
추가로 입력/fmap 버퍼의 두 8-bit 읽기 출력을 비교했다. 불일치는 cycle·신호·양쪽 값을 출력하고 fatal 처리한다.
MAC이 실제로 소비하는 유효 activation/weight에는 X가 없는지도 검사했다.

| 입력 | START~완료 포함 비교 에지 | START→완료 수락 경과 주기 | done 펄스 | 불일치 |
|---|---:|---:|---:|---:|
| 결정적 패턴 | 1,278,890 | 1,278,889 | 1 | 0 |
| xorshift32 0x6e01cafe | 1,278,890 | 1,278,889 | 1 | 0 |
| 합계 | **2,557,780** | — | 2 | **0** |

`Pool.v:138`의 조합 enc_done이 처음 1로 관측된 시각은 START 기준 1,278,888 주기 후,
그 done을 수락하고 마지막 결과 쓰기를 완료하는 에지는 1,278,889 주기 후다.
START 에지 자체도 비교에 포함하면 1,278,890개다. 속도가 1 cycle 바뀐 것이 아니다.
완료 전후 표본만 보는 방식으로 줄이지 않았다.

실행 중 feature 주소를 계속 0~511로 순환했다. 아직 안 쓴 주소와 범위 밖 주소의 X는 case equality로 비교했다.
실행 후에는 별도로 전 주소를 1-cycle 읽기로 검사했다.

| 입력 | 실행 중 알려진 feature 표본 | X 포함 표본 | 완료 후 유효 word 전량 | 범위 밖 X | 0이 아닌 유효 word |
|---|---:|---:|---:|---:|---:|
| 결정적 | 440,704 | 838,186 | 384/384 일치, X 없음 | 128/128 | 384 |
| 난수 | 959,231 | 319,659 | 384/384 일치, X 없음 | 128/128 | 384 |

난수 입력에서는 결정적 입력 대비 유효 feature **384개 모두 값이 달라졌다**.
따라서 최종 비교 성공이 양쪽 X 또는 고정 0만 비교한 결과는 아니다.
두 실행의 유효 최종 데이터 비교량은 768 word = 6,144 byte다.

추가 Buffer 독립 검사:

| W/R | 저장 byte | 검사 수 | 같은 에지 읽기/쓰기 겹침 | 결과 |
|---|---:|---:|---:|---|
| 64/8 실제 입력 | 11,520 | 36,200 | 11,521 | 1-cycle / LSB=낮은 주소 / read-first 일치 |
| 8/8 실제 fmap | 20,480 | 82,120 | 20,481 | 동일 |
| 8/64 역방향 | 64 | 288 | 29 | 동일 |
| 24/8 비율 3 | 60 | 400 | 68 | 원본 경로 동일 |
| 64/16 비율 4 | 64 | 304 | 52 | 신규 경로 동일 |

합계 **119,312 검사**, collision **32,151회**, 불일치 0.
각 주소 전량 읽기와 모든 lane 충돌을 수행하고, byte 배열 golden을 독립적으로 갱신했다.
주소 변경 후 클록 전 출력 유지 검사도 포함한다.

최종 xsim wall-clock **77.089초**, xvlog 1.118초 + TB xvlog -sv 1.019초 + xelab 5.339초.
최종 compile/elaboration 오류·경고 0. xsim exit code만 믿지 않고 최종 PASS, `$finish`, FAIL/Fatal/ERROR 부재를 함께 확인했다.

## 5. 합성: BRAM 목적 달성, 타이밍은 실패

Vivado 2020.2, `CNN_Encoder` OOC, `xc7z020clg400-1`, 기존 `syn/timing_100mhz.xdc`.
주기 10 ns, 입력/출력 지연 각 2 ns. 검증 후보 6개를 직접 읽었다. 합성 wall-clock **72.344초**.

| 대상 | LUT | FF | RAMB36 | RAMB18 | DSP |
|---|---:|---:|---:|---:|---:|
| CNN_Encoder 전체 | **6,490** | **3,530** | **13** | **0** | **10** |
| u_input_buf | 884 | 3 | **4** | 0 | 0 |
| u_fmap1_buf | 0 | 0 | **8** | 0 | 0 |
| u_pool | 1,829 | 2,113 | 1 | 0 | 3 |
| u_conv_mac | 1,527 | 1,214 | 0 | 0 | 0 |

두 Buffer의 저장소는 모두 RAMB36E1이다. 입력 92,160 bit, fmap 163,840 bit를 담는다.
LUTRAM 0, 전체 SRL 27개, 래치 0, 조합 루프 0, latch loop 0.
용량을 BRAM 용량으로 단순 나눈 최소 개수가 아니라 실제 추론된 primitive 개수를 보고했다.

| 경로 범위 | WNS | 주요 경로 | 데이터 지연 / logic level |
|---|---:|---|---|
| 전체 | **−3.641 ns** | `u_enc_rq/param3_reg[69]/C` → `u_enc_rq/rq_reg[1]/R` (2/3에도 동일) | 13.033 ns / 31 |
| Conv_MAC 내부 FF→FF | **+1.325 ns** | `s2_layer_reg/C` → `g_lane[0].lane_acc_reg[29]/D` | 8.700 ns / 12 |
| Conv_MAC으로 들어오는 경로 포함 | **−0.798 ns** | 입력 Buffer BRAM `mem_reg_1/CLKBWRCLK` → 같은 lane_acc D | 10.823 ns / 13 |

전체 TNS **−447.829 ns**, setup failing endpoint **684개**.
이전 Conv_MAC 단독 +1.093 ns와 현재 내부 +1.325 ns의 수치 차이는 +0.232 ns다.
그러나 경계·주변 논리가 다른 합성이므로 **기존 여유가 전체 Encoder에서 유지됐다고 결론 내릴 수 없다**.
특히 실제 BRAM에서 MAC으로 들어가는 연결 경로가 음수다.

따라서 입력 Buffer 때문에 합성이 막히던 문제는 해결됐지만 **100 MHz 동작 가능 판정은 하지 않는다**.
requant/Conv/Pool 내부 수정, pipeline 추가, 주기 변경은 이번 금지 범위이므로 적용하지 않았다.
후속 타이밍 조치의 범위와 지연 계약은 별도로 검수·결정해야 한다. P&R/hold/보드 검증도 미실시다.

합성 실행 전체에는 기존 Common 17-741(Tcl store), Timing 38-242(OOC clock skew),
Vivado 12-180(래치 검색 결과 0개) 경고가 있다. compile/elaboration 경고 0과 구분한다.
RAM 출력 추가 레지스터를 합치지 못했다는 Synth 8-7052 INFO도 있다. 읽기 지연 계약을 바꾸는 추가 파이프라인은 넣지 않았다.

## 6. 보호 파일 및 기존 회귀

원본 14파일 + 기존 RTL/TB 33파일 = **47파일 SHA-256 무변경**.
우리 Top/Loader/S00/M00 포함. 수정 금지인 Encoder 3개는 후보에서도 원본과 byte 동일하다.
[전체 해시 및 최초 복사 기록](E-01_hash_audit.json), [읽기 쉬운 해시·회귀 표](E-01_hash_audit.md).

| 묶음 | TB 수 | 실행 결과 |
|---|---:|---|
| Top 통합 LOAD / INFER / FC1 / FULL | 4 | 각각 10 / 13 / 11 / 13 case 모두 PASS |
| ctrl_status / csr_ctrl_link | 2 | PASS |
| S00 write / regs / read / ctrl | 4 | PASS |
| M00 read / perf / write / err | 4 | PASS, 처리율 지연 4종 포함 |
| AXI 메모리 자체시험 | 1 | PASS, 의도한 negative case 포함 |
| Blob Decoder / Loader RAM / wrapper / real blob | 4 | PASS |
| 합계 | **19** | **기존 소스 무수정** |

기존 L-07 결과와 PASS/OBS **1,342줄이 완전히 동일**하다. 기존 기대값을 고쳐 통과시키지 않았다.
해당 회귀는 우리 기존 모듈 보호 확인이며 실물 Encoder와 전체 Top의 X-02 결합을 대신하지 않는다.

후보 패치와 증거는 검수 가능하다. 공유 작업본은 동시 편집 종료 확인을 기다린다.
원본 손상이나 검수자의 파일을 덮어쓰는 방식으로 반영하지 않는다.
E-01 검증의 기능/BRAM 항목은 통과했으나 타이밍 실패를 해결 완료로 표시하지 않는다.

## Notion 복사용 요약

> E-01 검증 후보: 입력 Buffer를 1,440×64-bit word RAM + 같은 에지에 보관한 byte index로 변경했다.
> 읽기 1-cycle, little endian, read-first 유지. W==R/W<R 원본 경로 보존.
> 실제 blob + 결정적/난수 입력으로 원본과 2,557,780개 에지, 외부 출력 5개 전량 대조 불일치 0.
> 각 실행 START/완료 포함 1,278,890개 에지, 실제 경과 1,278,889 cycle. 최종 유효 feature 384 word 전량 일치.
> 별도 Buffer 5구성 119,312 검사 통과. 기존 19 TB 무수정 통과, 보호 47파일 해시 동일.
> CNN_Encoder 합성 성공: LUT 6,490 / FF 3,530 / RAMB36 13(입력 4, fmap 8, Pool 1) / DSP 10, 래치·루프 0.
> **100 MHz WNS −3.641 ns로 타이밍 실패**. requant가 전체 임계 경로이며 Buffer→MAC도 −0.798 ns.
> 패치·후보 ZIP·전체 로그·동우 전달문 초안 작성. 공유 작업본 반영은 동시 편집 종료 확인 대기, 동우 전송 및 다음 단계는 미실시.
