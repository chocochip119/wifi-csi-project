# G-02 — 실제 Loader/Encoder와 C++ golden 수치 대조

2026-09-26. **검증 완료, H4 전량 일치, 검수 대기.** RTL 수정은 없다.
현재 입력 2회와 zero 입력 1회 모두 **384/384 word, 3,072/3,072 byte 일치**했다.
같은 입력의 재실행 결과도 같으며, 다른 입력에서는 RTL·golden 양쪽의 변화 위치와 값이 일치했다.
검증한 두 입력에 대한 기능 일치이며 모든 가능한 입력·재학습 모델의 형식적 등가성 증명은 아니다.

## 1. 변경 파일과 구성

신규 RTL/TB 소스는 [tb_golden_encoder.v](../testbench/tb_golden_encoder.v) **하나**다.
기존 `pose_cnn` 내부 실물 ctrl/Loader/Encoder와 FC 모형, 코어 밖 실물 M00와 AXI 메모리 모형을 연결했다.
S00 없이 reg_*를 직접 구동한다. 기존 RTL·stub·TB·golden은 수정하지 않았다.

| 위치 | 역할 |
|---|---|
| TB 220행 prepare_files | host 해시 검증 기록, 실제 blob/hex 읽기, 독립 RAM 기대값 계산 |
| TB 256행 fill_input | 현재/zero golden의 입력 binary를 1,440개 64-bit word로 공급 |
| TB 267행 command | START 수락·완료·deadline·status·AXI quiescent 확인 |
| TB 287행 scanner | enc_done 후 flat_raddr 0..383 순차 구동 |
| TB 294행 observe | 입력 쓰기 전량·Encoder cycle·동기 RAM 응답·주소 범위·D09 관측 |
| TB 348행 compare_flat | 포트에서 수집한 384 word와 byte 전량 비교, CSV/hex 저장 |
| TB 381행 diagnose_ram_ports | 불일치 때만 idle에서 상주 RAM 4종을 포트로 전량 읽기 |
| TB 419행 run_all | LOAD 1회 후 현재/반복/zero INFER 3회 및 H6 비교 |

기존 fc_stub의 RAM 검사 모드는 껐다. TB가 모형의 **기존 flat_raddr 출력 reg**에 주소만 구동하며,
반환되는 flat_rdata를 실제 포트에서 읽는다. FC start/done/FIFO는 원래 동작을 유지해 INFER를 정상 종료시킨다.
stub의 pose 결과는 판정에 쓰지 않는다. Pool 저장소 계층 값이나 write 버스를 golden으로 삼지 않았다.

## 3. H1 — 파일 동일성

blob은 `D:\2609_final_project\wifi-csi-pose-main\HLS\pl_accel_v6\pl_accel_v6_weights.bin`.
현재 입력은 `D:\2609_final_project\cnn_rtl\golden\golden_current\input_i8.bin`.

| 파일 | 크기 | SHA-256 |
|---|---:|---|
| blob | 422,992 B | `063d01b880c4d96f1fe61450a72a9911b222ebf67bbbbf560da700a7350b94bb` |
| 현재 INT8 입력 | 11,520 B | `949915442c9dfcf980d4880e52b4ff6b08b1b5ff75bdccfa346b807ba0c6fffa` |
| zero INT8 입력 | 11,520 B | `2ddbd07ddfda5d4f9b1c44c8ff16f7e38027d275af6bf57f317b136060d695a9` |

현재/zero 두 manifest 모두 COMPLETE이며 blob SHA가 위와 같다.
Python host가 blob·입력·golden hex 각각의 SHA와 크기/줄 수를 manifest에 대조한 뒤 simulation cwd에 snapshot을 만들었다.
snapshot도 전후 재해시했다. TB는 그 파일을 읽어 `$fread` byte 수와 EOF, header, golden 384개 비-X를 확인했다.
**SHA 계산은 host에서 수행한다.** TB가 암호학적 해시를 계산했다고 표시하지 않는다.
[두 manifest 및 staged SHA 전문](G-02_h1_complete.json).

H6 zero golden은 수정하지 않은 도구 사본에 `--reference-dir`, `--blob`, `--input-bin`, `--output` 경로를 주어 생성했다.
**3.194초** 걸렸고 원본/관측 C++ pose 비트 24개가 동일했다. [생성 명령·출력](G-02_zero_golden/run.log),
[zero manifest](G-02_zero_golden/manifest.json), [zero 입력](G-02_zero_golden/input_i8.bin),
[zero Encoder golden](G-02_zero_golden/encoder_flat_u64.hex).
기존 golden 폴더 안에서 생성 도구를 실행하지 않아 사본 작성도 기존 폴더에 발생하지 않았다.

## 4. H2/H3 — LOAD와 Encoder 완주

메모리 모형 기본 지연 조건. BASE=0x10000000 / INPUT=0x20000000 / OUTPUT=0x30000000.
공통 reset → LOAD 1회 → INFER 3회 순서이며 INFER 사이 reset/재LOAD는 없다.

| 항목 | 이번 관측 | X-02a | 차이 |
|---|---:|---:|---:|
| LOAD | **10,114 cycle** | 10,114 | **0** |
| Encoder START 수락→done | **1,278,889 cycle**, 세 실행 동일 | 1,278,889 | **0** |
| 입력 RAM 기록 | **1,440 word**, 각 실행 주소·값 전량 일치 | 1,440 | 0 |
| enc_start / enc_done | **각 1회**, 각 실행 | 각 1회 | 0 |
| flat 포트 수집 | **384회**, 각 실행 | 384 | 0 |

LOAD 종료는 cfg_ok=1, error=0, output_scale_bits=**0x3BD997A8**.
각 INFER는 done=1/error=0이며 M00 read/write busy=0과 quiescent를 확인했다.
전체 INFER 시간은 **1,335,832 cycle**이다. X-02a의 1,338,265보다 2,433 짧다.
이는 FC RAM 전량 읽기용 지연 2,052/388 대신 이번에는 기존 stub 기본 3/4를 쓴 차이
`(2052−3)+(388−4)=2433`이며 Encoder 속도가 달라진 것이 아니다.

## 5. H4 — 전량 비교

| 실행 | 입력 | 일치 word | 불일치 word | 일치 byte | 불일치 byte |
|---|---|---:|---:|---:|---:|
| 0 | G-01 현재 샘플 | **384** | **0** | **3,072** | **0** |
| 1 | 같은 샘플 재실행 | **384** | **0** | **3,072** | **0** |
| 2 | zero 입력 | **384** | **0** | **3,072** | **0** |

불일치가 없어 첫 5개 예시와 rx/oc/oh 집중도는 없다. 합계 **1,152 word / 9,216 byte 대조, 불일치 0**.
TB는 enc_done 다음 하강 에지부터 주소를 공급하고, 다음 상승 에지의 RAM 갱신 후 `#1`에 값을 수집한다.
낮은 byte 주소를 word 하위 8 bit로 해석한다. golden 또는 출력의 순서를 사후 보정하지 않았다.

[전체 비교 CSV](G-02_flat_all_words.csv), [실행 0 포트 덤프](G-02_rtl_flat_run0.hex),
[실행 1 포트 덤프](G-02_rtl_flat_run1.hex), [실행 2 포트 덤프](G-02_rtl_flat_run2.hex).
시뮬레이터 종료 뒤 Python으로도 1,152개 CSV 행의 주소 순서·golden/actual·불일치 마스크 0을 독립 확인했다.
세 포트 덤프를 원 golden과 값별로 다시 비교했다. xsim 파일의 CRLF와 Python golden의 LF 차이는 데이터 차이가 아니므로
hex 텍스트 파일끼리의 raw SHA가 같아야 한다고 요구하지 않는다.

이 결과는 대상 blob/입력에서 Loader scatter·Param/LUT 배치·pool 파라미터 전달·ENC 선택·Flatten 순서와
실물 Encoder 연산을 함께 통과한 근거다. 개별 모듈의 모든 입력 조합에 대한 독립 증명을 뜻하지 않는다.

## 6. H5 — 불일치 진단은 생략, 수집한 실행 관측

**H4가 모두 통과해 상주 RAM 4종의 추가 포트 sweep은 실행하지 않았다.** 실행한 것으로 보고하지 않는다.
H5용 분기는 TB에 준비되어 있지만 이번 검증에서 사용하지 않았다.
실행 중 수집한 주소·응답은 다음과 같다.

| 실행 | Param raw/valid 범위 | LUT raw/valid 범위 | 범위 밖 / valid X | D09 / pool 전달 불일치 |
|---|---|---|---|---|
| 현재 | **0..47** | **1..497** | 0 / 0 | 0 / 0 |
| 현재 반복 | **0..47** | **1..497** | 0 / 0 | 0 / 0 |
| zero | **0..47** | **92..431** | 0 / 0 | 0 / 0 |

LUT는 모두 table 0~1(주소 0..511) 안이다. pool_mult=**0x783B66B4**, pool_shift=**31**의 header 값과
Encoder 입력을 ENC 동안 계속 비교했다. D09 두 선택 신호도 ENC 동안 모두 0이었다.

| 실행 | Conv / Param / LUT 동기 응답 비교 횟수 | 값/1-cycle 응답 불일치 |
|---|---|---|
| 현재 | 1,278,889 / 1,278,841 / 1,278,836 | **0 / 0 / 0** |
| 현재 반복 | 1,278,889 / 1,278,889 / 1,278,889 | **0 / 0 / 0** |
| zero | 1,278,889 / 1,278,889 / 1,278,889 | **0 / 0 / 0** |

첫 실행에서 아직 알려지지 않은 비유효 주소는 값 대조 대상에서 제외했다. 유효 요청의 주소 X는 별도 계수로 **0**을 확인했다.
이 기록은 실행 중 응답 관측이며 H5의 RAM 전량 sweep과 구분한다.

## 7. H6 — 재현성과 다른 입력 반응

- 같은 입력 2회: 서로 다른 word **0/384**, byte도 동일.
- 현재→zero: RTL **384/384 word, 2,957/3,072 byte 변경**.
- 같은 변경의 C++ golden: **384/384 word, 2,957/3,072 byte 변경**.
- 두 입력 각각에서 전체 값이 golden과 일치하므로, 변화 개수만 우연히 같은 검사가 아니다.

FC 모형의 고정 pose는 이 판정에 사용하지 않았다. 실제 Encoder flat 포트 결과를 비교했다.

## 8. H7 — 회귀와 원본 보존

기존 **21 TB 모두 수정 없이 재실행해 통과**했다.
Top 통합 4 + 상태/CSR 2 + S00 4 + M00 4 + AXI 모형 1 + Loader 4 + Encoder 등가성 1 + X-02a 코어 1.
각 TB의 PASS/OBS를 X-02a 결과와 비교했고 **1,385줄의 관측값이 모두 같다**.
[TB별 집계](G-02_regression_summary.json), [명령·출력 전문 및 실행 스크립트](G-02_regression_logs).

작업 전 파일 집합과 SHA-256을 대조했다. **384개 기존 파일 무변경**:
참고 저장소 299 + RTL 17 + TB/stub 26 + others 14 + golden 28.
새 `tb_golden_encoder.v`만 승인 범위의 소스 추가다. [전후 SHA 전문](G-02_hash_audit.json).
기존 21 TB에는 기대값·포트·조건 수정이 없다. 합성은 수행하지 않았다.

## 9. 실행 기록과 한계

Vivado 2020.2. RTL은 xvlog, TB/모형은 xvlog -sv, elaboration은 xelab.
최종 xvlog **1.152초**, xvlog -sv **1.149초**, xelab **6.796초**, 신규 xsim **63.030초**.
세 Encoder 실행을 포함한 wall-clock이다. [실제 명령·출력 전문](G-02_g02_run.txt),
[사용한 host runner](G-02_run_g02.py).
H1을 통과한 뒤에만 실행했으며, xsim exit=0 외에 완료 표식·finish·fatal 부재·**H4_pass=1**을 함께 확인했다.

최초 신규 TB에서 block-local 변수 선언 초기화가 VRFC 10-3824 경고를 냈다.
선언과 초기화를 분리한 뒤 다시 컴파일해 **최종 xvlog/xvlog-sv/xelab 오류·경고 0**.
[초기 경고 기록](G-02_initial_compile_warning.txt)을 따로 남겼다. 기존 RTL/TB는 고치지 않았다.

재실행 준비: 보고서에 보존한 `G-02_zero_golden/`를 `%TEMP%/codex-g02/golden_zero/`에 복사하고
`G-02_run_g02.py`를 실행하면 현재 원본/manifest 해시 확인, snapshot 준비, 빌드와 세 case 실행을 다시 한다.
runner의 현재 프로젝트/도구 절대경로는 이 PC 기준이다. 경로가 바뀌면 runner의 r/w/Vivado 경로를 맞춘다.

이번 검증으로 FC 구현·실물 FC 수치 검증은 하지 않았다. Encoder의 기존 100 MHz 타이밍 실패도 해결된 것으로 간주하지 않는다.
현재 두 입력의 기능 비교가 통과한 것이며 다음 단계의 구현 승인을 대신하지 않는다.
