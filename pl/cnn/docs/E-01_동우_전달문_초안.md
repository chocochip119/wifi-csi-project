# 동우 전달문 초안 — 전송하지 않음

Encoder 원본은 그대로 두고 입력 Buffer 저장 구조를 바꾼 후보를 만들었습니다.
기존에는 64-bit 입력 하나를 8-bit 배열의 8주소에 동시에 썼는데,
후보는 1,440×64-bit 배열의 한 주소에 쓰고 읽을 word와 byte index를 같은 클록에 저장합니다.
하위 byte가 낮은 주소인 순서, 읽기 1-cycle, 동시 읽기/쓰기의 기존 read-first 동작을 유지했습니다.
W==R/W<R 경로는 원래 동작을 그대로 남겼습니다.

Buffer/Pool/gelu_stage에는 timescale만 필요한 만큼 추가했습니다.
CNN_Encoder/Conv_MAC/requant_stage는 원본과 byte 동일합니다.

실제 reference blob을 실물 Loader에 적재하고, 결정적 입력과 난수 입력 두 번에 대해
원본과 후보 Encoder를 나란히 실행했습니다. 총 2,557,780개 에지에서 5개 외부 출력과
두 버퍼 읽기 출력을 비교했고 불일치가 없었습니다. 완료 후 384개 유효 feature word도 전량 같습니다.
기존 1,278,890은 START와 완료 에지를 모두 포함한 개수이며, 두 에지 사이 경과는 1,278,889 cycle이었습니다.
원본과 후보가 정확히 같은 에지에 끝납니다. 별도 Buffer 검사 119,312회도 통과했습니다.

xc7z020clg400-1 OOC 합성은 성공했습니다. 입력 Buffer 4개, fmap Buffer 8개,
Pool 1개의 RAMB36이 사용됩니다. 전체 LUT 6,490 / FF 3,530 / DSP 10, 래치·조합 루프 0입니다.

다만 **100 MHz 타이밍은 아직 통과하지 못했습니다.** 전체 WNS는 requant 경로의 −3.641 ns이고,
입력 Buffer BRAM→MAC 누산 경로도 −0.798 ns입니다. MAC 내부 FF 간에는 +1.325 ns입니다.
Buffer 합성 문제를 해결한 패치이며 Encoder 전체의 타이밍 완료 패치는 아닙니다.
지연 계약에 영향을 줄 수 있어 requant/Conv 파이프라인은 건드리지 않았습니다.

원본 대비 [패치](E-01_encoder_patch.diff), 검증한 [후보](E-01_encoder_candidate.zip),
[전체 검증 기록](E-01_구현_검증기록.md), [해시](E-01_hash_audit.json)를 함께 확인 부탁드립니다.
원본 14파일과 기존 RTL/TB 33파일은 바뀌지 않았고 기존 19개 TB도 그대로 통과했습니다.
이 패치를 원본에 채택할지는 동우가 판단하면 됩니다.
