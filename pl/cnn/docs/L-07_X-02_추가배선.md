# L-07 D09 확정 — X-02 추가 배선 계약

2026-09-26 사용자 확정 C안. 이 문서는 X-02 인계 목록이며 코어 배선을 구현한 것은 아니다.

| 신호 | 폭 | 구동 | 수신 | 의미 |
|---|---:|---|---|---|
| `param_sel_fc` | 1 | `pose_cnn_ctrl.param_sel_fc` | `weight_param_loader.param_sel_fc` | 0: `enc_param_raddr`, 1: `fc_param_raddr` 선택 |
| `lut_sel_fc` | 1 | `pose_cnn_ctrl.lut_sel_fc` | `weight_param_loader.lut_sel_fc` | 0: `enc_lut_raddr`, 1: `fc_lut_raddr` 선택 |

- 두 신호는 현재 상태 FC1/FC2/FC3에서만 1이다. ENC를 포함한 다른 상태와 불법 인코딩에서는 0이다.
- 상태 조합 출력이며 별도 레지스터가 없다. X-02에서 두 출력과 동명 Loader 입력을 각각 직접 연결한다. 현재 두 값이 같아도 외부 포트는 따로 유지한다.
- Loader는 읽기 **주소**를 고른다. 물리 RAM 포트는 각 1개이며 읽힌 데이터는 ENC/FC 양쪽 출력에 동일하게 전달된다. 소비자는 자신의 동작 구간에서만 사용한다.
- Encoder가 완료 후 주소 잔값을 계속 내도 FC 선택 중에는 무시한다. OR 연결이나 미사용 주소=0 가정을 쓰지 않는다.
- Conv/FCW 읽기 배선은 그대로다. RAM 읽기 지연은 1-cycle이며 추가 데이터 mux/파이프라인은 없다.

## 전환 에지와 소비 시점

| 시점 | 현재 상태 / 선택 | RAM 동작 |
|---|---|---|
| ENC 완료를 수락하는 상승 에지 직전 | ENC, `fc_start=1`, `fc_sel=0`, 선택=0 | 아직 Encoder 주소가 보인다 |
| 같은 상승 에지 직후 | FC1, 선택=1 | 그 에지에 샘플한 Encoder 주소의 데이터가 출력된다 |
| 다음 상승 에지 직후 | FC1, 선택=1 | FC 주소로 읽은 첫 데이터가 출력된다 |
| FC1→FC2→FC3 | 선택=1 유지 | 각 에지의 FC 주소에 대한 데이터를 1-cycle 계약대로 받는다 |
| FC3→WR 상승 에지 직후 | WR, 선택=0 | 완료한 읽기는 전이 직전 FC 주소의 데이터이며, 다음 에지부터 Encoder 주소가 반영된다 |

FC가 `fc_start`를 받는 에지에 자기 Param/LUT 데이터까지 이미 유효하다고 가정하면 안 된다.
실물 FC의 주소 발행/데이터 소비 파이프라인을 X-02에서 이 계약과 대조해야 한다.

## 검증 범위와 남은 통합 확인

L-07은 실제 Top 선택 출력과 실제 Loader 주소 mux/RAM을 연결해 위 시점과 잔값 무시를 검증한다.
기존 Encoder/FC stub에는 RAM 주소 포트가 없어 TB 안에 별도 주소 구동 모형을 두었으며,
실물 Encoder/FC 연산이나 전체 LOAD 배선 완료를 뜻하지 않는다.

Top/Loader 각각의 OOC 합성은 통과했지만 **Top 상태 FF → 선택 신호 → Loader mux → BRAM** 전체 타이밍은
단독 합성 두 번으로 증명되지 않는다. X-02/X-03 통합 및 구현 단계에서 확인한다.
D09는 확정됐으며, D07 공통 reset의 생성·공급 및 실제 reset 범위 검증은 별도로 남아 있다.
