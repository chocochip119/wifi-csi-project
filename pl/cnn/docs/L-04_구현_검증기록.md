# L-04 Loader 상위 모듈 구현·검증

작성: 2026-09-26, Codex. L-04 구현·자체 검증 완료. Claude 검수와 사용자 확인 전이며 다음 단계는 시작하지 않았다.

`weight_param_loader`로 기존 Blob Decoder와 RAM 4종을 묶었다. 외부 포트 24개는 명세와 이름·폭·방향이 모두 일치한다. RAM 쓰기 버스는 내부에만 있다. 새 순차 로직 없이 배선과 Param/LUT 주소 mux만 추가했다.

외부 읽기 포트로 RAM 전량 대조, 1-cycle 읽기, 오류/reset, 정상 9,772 cycle 유지 검사를 통과했다. 기존 17 TB도 무수정 통과했다. 합성 LUT631 / FF212 / RAMB36 10+RAMB18 3 / WNS+1.365ns로 L-03 최종 결합과 같다. **FC 주소 선택은 아직 지원하지 않는다.** `fc_active=0`인 이번 범위에서는 Param/LUT의 두 소비자 출력 모두 Encoder 주소의 데이터다.

## 1. 구현 전 원문 확인과 명세 보정

[원문 XLSX](D:/2609_final_project/IP_v1_0/IP_v1_0/interface_spec/Pose_CNN_IP_Interface_Spec.xlsx)의 `05_Loader` r8~r31, r86, r99와 현재 RTL을 직접 대조했다.

1. 기존 `loader_l02_synth.v`도 이미 외부 24포트의 이름·폭·방향이 원문과 같았다. “fixture 포트가 일치하지 않는다”는 설명은 현재 파일과 다르다. 이번 변경의 목적은 정식 RTL 경계 모듈과 명시적인 상위 주소 mux를 마련하는 것이다. 기존 fixture의 쓰기 버스도 내부였으므로, 쓰기 버스를 숨기는 것 자체가 이번에 새로 얻는 타이밍 완화는 아니다.
2. K3의 “6개 포트 모두 주소 다음 cycle 데이터”는 **선택된 주소 기준**이다. K4의 enc 고정과 함께 해석해야 한다. FC의 Param/LUT 주소로 독립 읽기가 된다고 검사하면 현재 승인된 계약과 충돌한다. 두 출력의 1-cycle 지연은 검사하되, 기대값은 둘 다 enc 주소로 정했다.
3. XLSX r9에는 옛 “비동기 assert/동기 release” 문구가 남아 있다. 사용자 확정과 공통 문서 5.2절에 따라 **동기식 active-low reset**을 유지한다. 원문을 수정하지 않았다.

기존 Param/LUT RAM은 enc 입력을 물리적 읽기 주소로 사용하는 임시 구조다. RAM을 바꾸지 않고 상위 mux 결과를 두 기존 주소 입력에 연결했다. 선택은 상위 한 곳에서만 담당하고 RAM의 1-cycle 읽기 및 두 출력 broadcast는 그대로 쓴다. D09 선택 신호의 출처는 결정하지 않았다.

기존 RTL/TB **30파일 SHA-256 무변경**이다. Blob Decoder, RAM 4종, Top, M00/S00, stub, 메모리 모형, 기존 17 TB를 포함한다. 신규 상위 RTL에는 `for/task/function/initial/generate/genvar`가 없고 `always` 블록도 없다. Decoder의 현재 기본 parameter(`CHECK_VERSION=1`, version2 등)를 override 없이 사용했다.

읽기 경로는 다음과 같다.

- Conv/FCW: 외부 주소 → 해당 RAM → 외부 데이터. 주소 mux나 추가 레지스터 없음.
- Param/LUT: `fc_active ? fc 주소 : enc 주소` → 기존 RAM의 읽기 입력 → 두 논리 출력에 같은 등록 데이터.
- `fc_active`는 내부 wire이며 상수0. L-07에서 합의된 실제 신호로 바꿀 주석을 RTL/TB에 남겼다. Top 상태를 계층 참조하거나 FC busy를 새로 추정하지 않았다.

예를 들어 enc Param 주소=10, fc Param 주소=147을 클록 사이에 주면 두 출력은 이전 값을 유지한다. 다음 상승 에지 뒤 두 출력 모두 Param[10]이 된다. fc Param[147]을 읽는 기능은 이번에 활성화하지 않았다. 상위에서는 RAM 내용을 reset하지 않는다.

## 5. 합성 비교

Vivado2020.2, xc7z020clg400-1, 기존100MHz OOC 제약으로 **1회** 실행했다. `weight_param_loader`를 top으로 지정하고 의존 RTL 5개를 함께 읽었다. `loader_l02_synth`는 이번 합성에 사용하지 않았다.

합성 실행에는 기존 Common17-741 CRITICAL WARNING(Tcl store 접근권한), Timing38-242 WARNING(OOC clock 위치), Vivado12-180 WARNING(래치 검색 결과0개)가 있다. 새 RTL 오류는 없으며 시뮬레이션 compile/elaboration 오류·경고0과 구분한다. P&R/hold·보드 검증은 하지 않았다.

## 7. 미결과 Notion 복사용 요약

D09의 `fc_active` 출처와 선택 전환 시점은 여전히 미결이다. 상위 mux 자리는 마련했지만 현재 FC Param/LUT 독립 접근은 안 된다. 따라서 포트 표는 X-02 배선 기준으로 쓸 수 있어도 **완전한 Encoder→FC 읽기 전환까지 검증된 Loader**로 취급하면 안 된다. 실물 Top/M00/Encoder/FC 연결과 reference blob golden 대조는 이번 범위가 아니다.
