# L-07 구현·검증 기록 — D09 Param / GELU LUT 읽기 포트 선택

2026-09-26. **사용자 확정 C안 구현 및 S1~S6 자체 검증 완료. Claude 검수·사용자 확인 대기.**
이번 작업은 L-07까지이며 L-06/X-02 RTL은 만들지 않았다. Notion은 갱신하지 않았다.

## 1. 결정과 실제 구현 범위

사용자는 Top의 `param_sel_fc` / `lut_sel_fc` 출력 → Loader 입력인 C안을 확정했고,
명세에 빠진 `tb_csr_ctrl_link` 및 `tb_loader_real_blob`의 최소 포트 보정도 승인했다.
선택은 **현재 상태 FC1/FC2/FC3에서만 1**, 그 밖에는 0이다. 별도 레지스터는 없다.

구현 전에 확인한 명세 보완 사항:

- “기존 18 TB”는 L-05 실제 blob TB를 포함하면 **19종**이다. 모두 기본 실행으로 돌렸다.
- 기존 Encoder/FC stub에는 Param/LUT 주소 포트가 없다. 보호 대상 stub은 수정하지 않고,
  `tb_top_full` 안에 주소 구동 모형과 **실제 `weight_param_loader`**를 추가해 S3를 검사했다.
- “D01~D09 모두 닫힘”은 범위를 넓힌 표현이다. D09는 확정됐지만 D07의 reset 생성·공급,
  실제 reset 범위 검증은 X-03에 남아 있다. 실물 Encoder/FC 통합과 weight 내부 순서 golden 판정도 별도다.
- Top/Loader 단독 합성 2회로 전체 Top 선택 출력→Loader BRAM 경로 타이밍을 증명할 수는 없다.
  이번 수치는 각 블록 OOC 결과이며 통합 타이밍은 X-02/X-03에서 확인한다.

Top의 기존 13상태 인코딩·상태 전이·D02/D03/D06/D08 처리는 그대로다.
Top 포트 45→47, Loader 포트 24→26. Loader 내부의 `fc_active=0`을 제거하고,
Param 9-bit 주소와 LUT 10-bit 주소를 각각 선택 신호로 고른다.
읽은 데이터는 기존처럼 ENC/FC 두 출력에 **같이** 나온다. 물리 읽기 포트가 두 개가 된 것은 아니다.
Conv/FCW에는 선택 회로를 추가하지 않았다.

예: ENC 주소가 Param=17, LUT=73인 채 끝나고 FC 주소가 다른 번지를 가리키면,
ENC 상태에서는 양쪽 출력이 Encoder 주소의 데이터를 보인다. FC1/2/3에서는
Encoder 잔값을 계속 남겨도 양쪽 출력이 FC 주소의 데이터를 보인다.

**에지 경계:** ENC→FC1 에지 직전에는 ENC 상태라 선택=0이며 `fc_start=1`이다.
그 에지에서 Top 상태가 FC1으로 바뀌고 선택=1이 되지만 RAM은 전이 직전 Encoder 주소를 샘플했다.
**다음 상승 에지 직후부터 FC 주소의 데이터가 나온다.** 이것이 주소 mux 앞단 + 동기 RAM의 1-cycle 계약이다.
FC1→FC2→FC3에서는 선택=1이 이어지고 FC3→WR 직후 선택=0으로 돌아온다.
실물 FC가 `fc_start` 샘플 에지에 Param/LUT 데이터도 이미 유효하다고 가정하면 안 된다.

## 5. 회귀 보존과 실행 기록

- Top LOAD 10 case, 입력 INFER 13 case/15회, FC1 11 case/14회, full 13 case/18회.
- 상태 TB START snapshot14회, CSR 연계 START7회/busy100 cycle/AXI busy read49회 유지.
- S00 4종, M00 4종(성능 지연4개 포함), AXI 모형 자체시험1종을 **무수정** 재실행.
- blob_decoder 및 loader_rams 2종도 **무수정** 재실행. wrapper 및 실제 blob 2종 PASS.
- 기존 상태 TB의 zero-output 감시 표본 수만 **200→217**. 추가 S2 검사17 cycle이 원인이며 정상 기능 기대값을 변경한 것이 아니다.
- full TB의 사전 적재 때문에 CSV의 절대 시각 원점은 뒤로 이동한다. START 기준 상대 cycle,
  beat/burst/오류/drain 관측을 포함한 기존 PASS/OBS는 동일하다.

19종 최종 출력 모두 성공 표식과 `$finish`를 확인했고 runtime FAIL/Fatal은 없다.
실제 실행한 xvlog/xvlog -sv/xelab에서 오류·경고 0이다. exit code만으로 성공을 판단하지 않았다.
모형 자체시험의 의도한 음성 프로토콜 검사는 기존대로 통과했고, 통합 시험의 미허용 프로토콜 위반은 0이다.

초기 추가 S2 로그에서 루프 인덱스가 반복해 16으로 출력되는 관측 문제를 발견했다.
실제 강제 `state_reg`를 직접 대조·출력하고 16-bit coverage를 검사하도록 TB만 보완했다.
해당 상태 TB를 재실행해 0~15 실제 상태/선택을 확인했다. 최종 S2 근거는 별도 재실행 로그다.
기능 RTL이나 다른 TB의 기대값은 이 보정으로 바뀌지 않았다.
