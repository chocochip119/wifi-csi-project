# X-02a 검증 설계와 명세 보정

2026-09-26. 코어 외부 포트는 [28개 원문 대조표](X-02a_코어_포트대조.md)를 기준으로 구현했다.
이 문서는 검증 방법을 기록한다. 실행 결과는 별도 최종 기록과 원문 로그가 기준이다.

## 승인 범위

신규 `rtl/pose_cnn.v`, `tb/tb_pose_cnn_core.v`, 확장 `tb/fc_stub.v`.
기존 `tb_top_fc1`/`tb_top_full`은 새 포트 연결만 추가했다.
사용자가 추가 승인한 `tb_top_infer`도 동일한 연결만 추가했다.
이 세 TB는 기존 문장·조건·기대값을 보존하며 기본 FC 모형 동작을 사용한다.

Top/Loader/Decoder/RAM 4종/Encoder/S00/M00/AXI 모형은 수정하지 않는다.
시작 시 E-01 검증 후보와 현재 `rtl/encoder` 6파일의 SHA-256이 같음을 확인했다.
따라서 E-01에서 보류했던 반영을 이번에 다시 수행하지 않았다.

## 구현 전 확인한 명세 충돌

1. W6의 '각 오류가 ERR_DRAIN을 거친다'는 D08/T-07과 충돌한다.
   DDR read 오류 세 위치는 ERR_DRAIN을 거친다. WR BRESP 오류는 마지막 B 응답 이후
   FINISH로 직접 가야 한다. 기존 ctrl을 변경하지 않고 이 확정 계약을 검사한다.
2. 기존 `fc_stub`은 고정 pose를 출력한다. 그대로면 W7의 입력 변화 검사는 불가능하다.
   새 `ram_test_enable`은 기본 0이며, 신규 코어 TB에서만 1로 설정한다.
   이 모드에서 실제 feature 384 word로 192-bit 결정적 digest를 만든다.
   실제 FC 수학이나 학습 모델의 pose 정확도를 검증하는 것이 아니다.
3. 명세에서 빠진 `tb_top_infer`도 FC 모형 인스턴스를 갖는다.
   새 포트 연결만 최소 수정하도록 사용자에게 승인받았다. 나머지 관측은 그대로다.
4. 원문상 코어 내부 실물은 ctrl/Loader/Encoder 3개다. 네 번째 인스턴스는 FC 모형이고,
   실물 M00는 코어 밖 TB에 있다. 코어 자체에는 AXI 포트가 없다.

## 순수 배선

코어는 `wire` 선언과 이름으로 연결한 인스턴스 네 개뿐이다.
`always`, `assign`, `initial`, `reg`, `generate`, 함수·태스크를 넣지 않았다.
Loader의 cfg_ok를 ctrl과 외부 포트로 동시에 연결한다.
fc의 flat 주소/데이터 선을 Encoder의 feat 주소/데이터 포트에 그대로 연결한다.
D09 select와 모든 소비 블록 신호는 코어 내부에만 존재한다.

FC 모형은 testbench 문법을 포함하므로 core는 합성 top이 아니다.
세 실물 구성 블록을 각각 기존 100 MHz OOC 제약으로 합성한다.

## FC 모형 확장

추가 포트 8개: Param 주소/데이터, LUT 주소/데이터, FCW 주소/데이터, flat 주소/데이터.
각 포트의 주소는 active 동안만 갱신하며 idle에서는 마지막 주소를 보존한다.
기존 start/done/FIFO/pose 동작과 타이밍은 `ram_test_enable=0`에서 유지된다.

통합 모드의 주소 범위:

| 단계 | Param | LUT | FCW | flat |
|---|---|---|---|---|
| FC1 | 48~175, 128개 | 512~767, 256개 | 유지 | 0~383, 384개 |
| FC2 | 176~303, 128개 | 768~1023, 256개 | 0~2047, 2,048개 | 유지 |
| FC3 | 304~327, 24개 | 유지 | 2048~2431, 384개 | 유지 |

FC2/3가 해당 범위를 끝까지 읽을 수 있도록 **새 코어 TB에서만** 지연을 2,052/388 cycle로 설정한다.
구형 TB의 기본 3/4 cycle과 fixed pose 값은 그대로다.
FC1에서는 모든 실제 weight 49,152 word를 FIFO로 소비한다.

FC 모형은 falling edge에 주소를 바꾸고 다음 rising edge의 RAM 결과를 직접 검사한다.
Param/LUT/FCW 기대값은 실제 blob의 독립 주소식으로 만든 배열이다.
flat 기대값은 FC 읽기 응답을 복사하지 않는다. TB가 Encoder Pool 결과 RAM의
**쓰기 주소·byte enable·쓰기 데이터**를 관측해 별도 scoreboard에 저장한다.
384 word에 X가 없고 모두 같은지 검사하며, 384~511은 사용하지 않는다.

오류 주입 중 추가로 확인한 경계: ERR_DRAIN에서는 D09 select가 0으로 내려가지만
FC는 active에 남는다. 따라서 이때 공유 RAM의 응답은 FC 요청에 대한 유효 응답이 아니다.
TB의 `ram_shared_owned`는 **검사기만** 소유권을 알게 하는 변수다. FC의 active/done/FIFO나
주소 발생을 바꾸지 않는다. 소유권을 잃은 Param/LUT 읽기는 별도 개수로 기록한다.
코어의 선택 데이터 검사는 그동안에도 계속 동작한다. 정상 실행에서는 소유권 없는 읽기 0건을 요구한다.
이 처리 없이 모든 FC 읽기를 golden과 비교하면 D08의 의도적인 폐기 구간을 기능 불일치로 오인한다.

시험 pose는 모든 feature word를 읽으며 누적한 192-bit digest다.
세 64-bit 부분은 각각 rotate/XOR, 합, 다른 rotate/XOR로 갱신한다.
동일 입력 재현성과 입력 변화가 실제 Encoder→flat→stub→WR→DDR를 통과하는지 보기 위한 값이다.
정답 pose나 FC 대체 구현이라고 주장하지 않는다.

## core TB 기본 실행

기본은 아래 6 case 전체다. 선택 실행은 `+CASE=0..5`를 쓸 수 있다.

| CASE | 흐름 |
|---:|---|
| 0 | reset → 실제 blob LOAD → 같은 입력 INFER 2회 → 입력 변경 INFER 1회. INFER 사이 reset 없음 |
| 1 | reset → LOAD 첫 burst의 beat 7에 RRESP 오류 → error 4, cfg_ok 0 |
| 2 | reset → 재LOAD → 입력 read beat 7 오류 → error 4, enc_start 0 |
| 3 | reset → 재LOAD → 실물 Encoder → FC1 read beat 7 오류 → error 4, FC active 유지 |
| 4 | reset → 재LOAD → 전체 INFER → BRESP 오류 → write 완료 후 error 5, drain 진입 없음 |
| 5 | 공통 reset → 재LOAD → 정상 재INFER. 전체 정상 복구 |

실제 Encoder 완주는 정상 4회 + FC1 오류 1회 + WR 오류 1회, 총 6회다.
입력 read 오류는 Encoder에 진입하지 않는 별도 INFER 요청이다.
기본 실행으로 6개 case를 전부 돌린 명령과 최종 성공 표식을 남긴다.

## 검사 독립성

- 외부 포트 이름/방향/폭을 XLSX r8~r37에서 읽고 RTL 선언과 독립 대조한다.
- byte 파일을 DDR에 넣고 별도 주소식으로 Conv/Param/LUT/FCW golden을 계산한다.
- 실제 input RAM 쓰기 1,440주소의 순서/값, FC1 FIFO push 49,152값, 소비 완료 배열 전량을 비교한다.
- DDR 출력 24 byte 전량을 stub pose와 대조하고 바로 앞뒤 word가 미기록인지 검사한다.
- 여섯 RAM 논리 출력은 rising edge 직전 선택/주소에 해당하는 값이 직후 출력되는지 확인한다.
  물리적으로 같은 read data를 방송하는 Param/LUT의 비선택 출력도 **선택된 주소 값**을 기대한다.
- Encoder가 idle일 때 주소에 X가 있을 수 있다. X를 정수 인덱스 0으로 변환하지 않는다.
  유효 requant 요청은 `acc_valid`, GELU RAM 요청은 내부 `rq_valid_r0`에 맞춰 주소 X를 금지한다.
- D09는 단순히 주소가 다르다는 것 외에 **양쪽 주소의 기대 데이터도 다른 cycle**을 세어,
  비선택 소스가 실제로 무시되었는지 입증한다. FC 잔값은 다음 INFER에서도 유지한다.
- XSIM 종료 코드 0만으로 통과시키지 않는다. warning/error/fatal 부재와 최종 PASS/finish를 함께 검사한다.

## 남은 범위

실물 FC 수치 검증, S00/wrapper/BD 연결, reset의 보드 범위, 100 MHz 타이밍 개선 및 golden 추론은 이번 단계에 포함하지 않는다.
