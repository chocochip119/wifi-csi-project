## 3. 동작과 주소식

READY=1/VALID=1 수락 에지에서 첫 쓰기를 수행한다. Param은 하위 32-bit를 먼저 쓰고, 보관된 상위 32-bit를 다음 WORK 에지에 쓴다. FCW는 수락한 64-bit를 같은 에지에 그대로 쓴다. LUT는 수락 에지에 byte0, 다음 WORK 7 cycle에 byte1~7을 쓴다. 외부 공급 데이터가 이후 바뀌어도 나머지는 저장된 beat를 사용한다.

예를 들어 beat 94의 하위/상위 word는 Param 주소 0/1의 bias에 쓰인다. beat 102에서는 주소를 다시 0/1로 하되 mult strobe만 켜므로 앞서 쓴 bias가 보존된다. shift도 같은 방식이다.

### Param — `09_Loader` r26~r35

아래 각 배열의 시작 beat를 `first`, layer base를 `base`라 하면 `base + 2×(beat−first)`와 그 다음 주소에 쓴다. **bias/mult/shift마다 first를 다시 적용**한다.

| Layer | base~마지막 | bias beat | mult beat | shift beat | 각 필드 수 |
|---|---|---|---|---|---:|
| Conv1 | 0~15 | 94~101 | 102~109 | 110~117 | 16 |
| Conv2 | 16~47 | 694~709 | 710~725 | 726~741 | 32 |
| FC1 | 48~175 | 742~805 | 806~869 | 870~933 | 128 |
| FC2 | 176~303 | 2982~3045 | 3046~3109 | 3110~3173 | 128 |
| FC3 | 304~327 | 3558~3569 | 3570~3581 | 3582~3593 | 24 |

strobe `001/010/100`은 각각 bias `[31:0]`, mult `[63:32]`, shift `[95:64]`를 선택한다. wdata에는 선택한 32-bit 값을 3필드에 복제하지만 RAM은 strobe로 지정된 필드 하나만 갱신한다. 총 328주소×3필드=984회 쓰기다.

### FCW·LUT

| 구간 | 주소 | 쓰기 수 |
|---|---|---:|
| FC2 weight, beat934~2981 | beat−934 → 0~2047 | 2,048 |
| FC3 weight, beat3174~3557 | 2048+beat−3174 → 2048~2431 | 384 |
| LUT, beat3594~3721 | 8×(beat−3594)+byte_index → 0~1023 | 1,024 |

LUT table 0/1/2/3은 각각 주소 0~255/256~511/512~767/768~1023이다. Loader는 이미 table 순서로 온 byte를 그대로 저장한다. 원문 r99의 `unsigned8(q) XOR 0x80`은 **추론 시 읽기 index 생성 규칙**이며, LOAD 쓰기 주소에 다시 XOR하지 않는다.

Conv weight는 `conv_we/waddr/wdata/wstrb=0`을 유지한다. RAM 자체의 byte strobe는 단독 TB로 확인했지만 decoder의 scatter는 L-03 범위다.

### 오류와 reset

shift 배열의 두 32-bit 값을 수락 에지 전에 signed 비교한다. 어느 쪽이든 `[-31,63]` 밖이면 해당 beat의 두 쓰기를 모두 억제하고 DRAIN으로 간다. 그 전의 유효한 쓰기는 보존되지만 cfg_ok는 0이며, 남은 beat를 READY=1로 버린 뒤 마지막 beat에서 done=1/err=1을 낸다. header 오류도 같은 drain 원칙을 유지한다.

마지막 LUT 처리 중 추가 VALID 검출은 L-01에서 사용자가 승인한 범위 그대로다. 오류 검출 에지부터 남은 LUT 쓰기도 막는다. 이 두 case의 쓰기 수는 1,017/1,023 byte이며 결과는 cfg0/err1이다. 완료 후 늦게 오는 추가 입력 검출 기능으로 확대하지 않았다.

RAM에 reset 포트가 없으므로 내용은 유지된다. decoder의 동기 reset 에지에는 `param_we/fcw_we/lut_we=0`으로 대기 중 쓰기도 차단한다. reset 후 cfg_ok=0이므로 유지된 부분 데이터를 유효 모델로 취급하지 않는다.

## 6. 합성 L1 — 실제 BRAM 추론

Vivado2020.2, xc7z020clg400-1, 기존100MHz OOC 제약. 단독4회와 결합1회, 총5회 수행했다. 모든 실행 래치0/조합루프0, setup failing endpoint0/TNS0이다.

| 대상 | LUT | FF | RAMB36 | RAMB18 | 36Kb 환산 | DSP | WNS(ns) |
|---|---:|---:|---:|---:|---:|---:|---:|
| conv_weight_ram | 0 | 0 | 2 | 0 | 2 | 0 | +3.565 |
| param_ram | 0 | 0 | 1 | 1 | 1.5 | 0 | +3.565 |
| gelu_lut_ram | 0 | 0 | 0 | 1 | 0.5 | 0 | +3.565 |
| fcw_ram | 0 | 0 | 7 | 1 | 7.5 | 0 | +3.565 |
| decoder+RAM4종 | **437** | **199** | **10** | **3** | **11.5** | **0** | **+1.801** |

RAMB36/RAMB18은 각각36Kb/18Kb primitive 개수다. 단독 RAM의 FF0은 동기 읽기 저장이 없다는 뜻이 아니라 BRAM 내부에 포함됐다는 뜻이다. FCW의 7+1은 이번 Vivado 추론 결과이며 논리 bit 수를 단순히36Kb로 나눈 최소 이론값이 아니다. 이번 범위에서 자원 최적화를 위해 구조를 변경하지 않았다.

결합 계층별 관측: decoder LUT383/FF199, Param 계층 LUT41 및1RAMB36+1RAMB18, Conv2RAMB36, LUT1RAMB18, FCW7RAMB36+1RAMB18. 전체 LUT437에는 합성기가 계층 경계에 배치한 논리가 포함된다. **상주 데이터 배열이 LUTRAM으로 풀린 것은 아니다.**

결합 임계 경로: `ld_data[8] → u_fcw_ram/mem_reg_0/ADDRARDADDR[10]`, LUT6단, data path6.522ns, WNS+1.801ns. 오류 판정이 쓰기 경로의 주소/enable 선택과 연결된다. L-01의 decoder 골격 단독+3.760과는 회로 범위가 달라 동일 기능 개선/악화 비교로 해석하지 않는다. 이번100MHz OOC 제약은 만족하며 배치·배선/hold 또는 실물 보드 검증은 하지 않았다.

실행 전체에는 기존 환경/제약 메시지3종이 있다: Common17-741 CRITICAL WARNING(Tcl store 권한), Timing38-242 WARNING(OOC clock 위치 미지정), Vivado12-180 WARNING(래치 셀 검색0개). 새 RTL 합성 오류는 없다. **시뮬레이션 compile/elaboration 오류·경고0과 합성 배치 경고를 구별한다.**
