## 첫 실행에서 발견한 경로 문제

첫 실행은 앞의 4개 TB가 통과했으나 XSIM이 한글 절대 경로의 BLOB plusarg를 잘못 해석해 실제 blob을 열지 못했다.
RTL/TB 문제가 아니며 run_checks.py에서 실행 폴더의 영문 파일명 blob.bin으로 복사한 후 SHA-256을 대조하고 상대 경로로 전달하도록 보완했다.
보완 후 위 5개를 모두 재실행해 통과했다. 실패 기록도 20260927_105219_618939/ 아래 보존했다.

## 무변경 및 파일 검증

- 원본에서 복사한 파일 1,109개, 74,320,803 byte.
- 모든 복사 파일의 SHA-256이 원본과 일치하며, 복사 전 기록한 SHA와 최종 원본 SHA도 전부 일치한다.
- RTL/TB/golden/동우 원본/참고 C++·blob에 변경 없음. 원본 프로젝트 문서에도 변경 없음.
- 신규 안내 문서의 상대 Markdown 링크를 확인했다.
- SOURCE_COPY_SHA256.json은 원본→복사본 매핑, MANIFEST_SHA256.json은 인계 payload 해시다.
- 실행 중 생성되는 runs/ 및 Python __pycache__는 payload manifest에서 제외한다. 최초 실행 로그는 이 verification/에 따로 보존하고 해시 대상에 포함한다.

## 재현 명령

인계 폴더 루트에서:

```powershell
python .\04_검증실행\verify_package.py
python .\04_검증실행\run_checks.py --vivado-bin C:\Xilinx\Vivado\2020.2\bin --suite smoke
```

과거 E-01~E-02a, G-02, F-03a 등의 상세 결과는 project/cnn_rtl/docs의 기존 근거다. 이번 복사본 재실행 결과와 구분한다.
