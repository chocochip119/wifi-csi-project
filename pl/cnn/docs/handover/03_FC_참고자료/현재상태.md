# FC 개발 중 산출물 — 완성된 FC 모듈 아님

[rtl/fc](../../../rtl/fc_work)의 fc1_weight_fifo.v / hidden_buffer.v / pose_buffer.v / fc_mac.v를 보존했다.
공유 requant는 rtl/CNN_Encoder/requant_stage.v에 있다. 별도 FC requant RTL은 없다.
FC golden 저장소/MAC/requant 검증 자료는 F-01/F-02/F-03a 보고서와 TB를 본다.

남은 구현은 FC GELU/hidden·pose 쓰기 경로, FC 제어 결합 및 fc_done/pose_data 완료 의미다.
FC 담당자가 현재 부품을 채택할지 별도 구현을 사용할지 결정해야 한다.
testbench/fc_stub.v는 FIFO 소비 속도·완료·pose를 흉내 내는 검증 모형이며 실제 FC나 합성 top이 아니다.

## 반드시 맞출 인터페이스

- fc_start 수락 에지에 fc_sel을 latch. idle일 때만 시작.
- fc_done은 결과 쓰기가 끝난 뒤 펄스. Top은 done을 보관한다.
- FC1 FIFO 512x64, full에서 write 금지, FWFT read. full 동시 pop/write에서도 write는 버린다.
- Param base 48/176/304, hidden packed/분리 주소 어댑터 확인.
- pose_data 192-bit는 FC3 완료 후 다음 INFER까지 유지. 하위 64 bit부터 3 beat로 write.
- FC1 중 오류 뒤 FC가 진행 상태에 남을 수 있다. 자동 중단/재START 성공을 가정하지 않는다. D08 실행 오류 reset 복구 적용.

[기존 요구사항 초안](../../T-05_FC_요구사항_초안.md)은 당시 초안이다.
위 요약과 F-03a/E-02a 최신 기록을 함께 전달한다. 이 폴더 작성만으로 FC 담당자에게 전달 완료한 것은 아니다.
