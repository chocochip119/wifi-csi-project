# 핵심 담당 범위와 파일

기준 경로: [rtl](../../../rtl).

아래 표는 담당 파일의 분류다. **검증에 사용한 상대 모듈과 유지해야 할 연결 조건**은
[인계 범위와 모듈 의존관계](인계범위와모듈의존관계.md)를 먼저 읽는다.

| 역할 | 파일 | 상태와 경계 |
|---|---|---|
| CSR | pose_cnn_v1_0_S00_AXI.v | 레지스터·START/CLEAR·STATUS·정렬·busy 접근 처리 |
| Top FSM | pose_cnn_ctrl.v | 13상태, LOAD/INFER/WR/ERR_DRAIN, D06·D08·D09 반영 |
| Loader 경계 | weight_param_loader.v | decoder와 RAM 4종 결합, 읽기 포트 선택 |
| Blob 해석 | blob_decoder.v | header/구간 검사 및 RAM 쓰기 생성 |
| 상주 RAM | conv_weight_ram.v, param_ram.v, gelu_lut_ram.v, fcw_ram.v | Loader 인계에서 빠뜨리지 말 것 |
| 수정한 AXI master | pose_cnn_v1_0_M00_AXI.v | 민영 원본 기반. reset 전환과 reset 중 VALID 게이트 변경 근거 포함 |

핵심 합성 소스 목록은 [core_rtl.f](../../../tools/core_rtl.f)에 있다. 이것은 단일 완성 top을 만드는 목록이 아니다.
Encoder/FC/pose_cnn을 RTL glob으로 한꺼번에 합성 소스로 추가하지 않는다.

## 변경한 M00의 출처

[R-01 변경 diff](../../R-01_변경.diff)와
[R-01 기록](../../R-01_구현_검증기록.md), T-02b/c/d의 read/write/오류 검증을 함께 인계한다.
별도 원본 M00 파일은 현재 작업 트리에 없으므로 원본인 것처럼 재구성하지 않았다. 현재 사용본과 당시 diff를 제공한다.
현재 테스트 계약은 매 `mem_wr_ready` HIGH 샘플마다 한 word 수락이다. 연속 HIGH는 연속 beat일 수 있다.
옛 T-02c 문서의 “연속 HIGH 금지” 실패와 현재 보정 TB를 혼동하지 않는다.

## 통합 참고본과 경계

[pose_cnn.v](../../../rtl/pose_cnn.v)는 ctrl + Loader + 실물 Encoder + fc_stub 연결이다.
S00/M00 AXI 버스 자체는 core 바깥에 있다. [포트 대조](../../X-02a_코어_포트대조.md)를 참조한다.
IP_v1_0의 wrapper는 기존 템플릿이며 최종 BD/패키징 완료본으로 표시하지 않는다.
