# R-01 — S00_AXI / M00_AXI 동기식 active-low reset 전환

날짜: 2026-09-25. **상태: 구현·검증 완료, 기존 TB 누적 6/6 PASS. Claude 검수·사용자 확인 대기.**

요청된 M00 이동, 비동기 sensitivity 4곳 제거, VALID 게이트 4곳 추가를 반영했다.
신규 reset b-1/b-2 검사는 통과했다. 최초 회귀는 4PASS/2FAIL이었으며,
명세의 **“기대값을 고쳐야 통과한다면 … 고치지 말고 보고할 것”**에 따라 먼저 보고했다.

reset 상승 에지 뒤로 옮겨 재실행했고 두 TB 모두 통과했다. 기존 기대값·검사 항목은 유지했다.
앞선 4개 PASS와 합쳐 누적 6/6 PASS이며 RTL은 추가 변경하지 않았다. T-02는 시작하지 않았다.

reset 동기화 회로도 추가하지 않았다.

## 3. 동작과 신규 reset 검사

순차 회로는 reset이 LOW인 **상승 에지**에 초기화된다. VALID 조합 게이트는
reset이 LOW인 동안 즉시 AXI 출력의 VALID를 0으로 만든다. 두 역할을 분리했다.

| 상황 | AXI 출력 | 내부 레지스터 |
| --- | --- | --- |
| reset LOW, 아직 상승 에지 전 | 지정된 READY/VALID 게이트가 0 출력 | 이전 값 유지; 시뮬레이션 최초에는 X일 수 있음 |
| reset LOW인 상승 에지 | 0 유지 | 명시된 reset 값으로 초기화 |
| 상승 에지를 놓친 짧은 reset 펄스 | LOW 동안 게이트로 0, 해제하면 보존된 상태가 다시 출력 | 초기화되지 않음 |

`tb_s00_axi_write` 신규 검사 결과:

- **b-1 PASS**: 10 ns clock에서 reset을 여러 상승 에지에 걸쳐 유지하여
  쓰기/CSR/읽기의 전체 순차 레지스터 213bit가 0이 되는지 검사했다.
  해제 직후 startup guard와 다음 정상 에지의 READY 동작, stale 응답·펄스 없음도 확인했다.
- **b-2 PASS**: 상승 에지 사이에 2 ns LOW 펄스를 넣어 AXI 5출력
  `{AWREADY, WREADY, BVALID, ARREADY, RVALID}`가 모두 0이 되는 동시에
  내부 레지스터 전체가 이전 값 그대로인지 검사했다. BVALID/RVALID가 모두 1인 응답 대기 상태와
  AWREADY/WREADY/ARREADY가 모두 1인 idle 상태에서 각각 확인했다.
  짧은 펄스가 레지스터를 지우지 않는 것을 정상 기대값으로 두었다.

b-2는 정상 reset 사용법이 아니라 공급 조건을 보여 주는 검사다. reset은 유효한
상승 에지를 포함하도록 충분히 유지해야 하며, 실제 생성 위치·유지 시간 결정은 D07에 남긴다.

## 4. 여섯 TB 최종 결과와 최초 실패 원인

Vivado 2020.2. RTL은 xvlog, TB는 xvlog -sv로 컴파일했다.
기존 write TB의 검사식 29개·기대 벡터가 유지됐다. 최초 실행 시 ctrl TB는 모형 sensitivity만
변경했고 regs/read/Top 두 TB의 파일 해시는 동일했다. 후속 보정은 regs/ctrl의 `tick`과
초기화 검사 순서 및 주석 한 줄씩으로 한정했음을 전체 소스 비교로 확인했다.
S00/M00/Top RTL 해시도 보정 전후 동일하다. 이번 재실행 대상은 regs/ctrl 두 TB다.

| TB | 결과 | 실제 확인 |
| --- | --- | --- |
| tb_s00_axi_write | PASS | 기존 AW/W/commit/B 각각 5회, 신규 b-1/b-2 모두 통과 |
| tb_s00_axi_regs | **PASS (보정 후 재실행)** | 초기/비영 값 설정 후 reset 포함 전체 검사 통과, 쓰기/commit/B 각 49회 |
| tb_s00_axi_read | PASS | AR=50/R=50, commit=7/B=7 |
| tb_s00_axi_ctrl | **PASS (보정 후 재실행)** | N=1/2/8 및 15a/15b/15c 포함 전체 검사 통과, PASS 로그 53줄 |
| tb_ctrl_status | PASS | START 14회, 미구현·불법 상태 복구 13건, 출력 0 검사 104cycle |
| tb_csr_ctrl_link | PASS | START=7, busy=14cycle, busy 읽기=6, busy COMMAND commit=1 |

최초 실행의 실패 원인은 두 TB에 남은 **비동기 reset 관찰 시점**이다. 아래 위치·출력은 보정 전 기록이다.

- [tb_s00_axi_regs.v:169](../testbench/tb_s00_axi_regs.v): `#2 rst_n=0; #1; check_regs(0); tick;`
  순서여서 첫 상승 에지인 5 ns보다 이른 3 ns에 초기화 값을 요구한다.
- [tb_s00_axi_ctrl.v:378](../testbench/tb_s00_axi_ctrl.v): 동일하게 3 ns에
  `{reg_start, reg_clear_status, bresp} == 0`을 요구한다.
  이 신호들은 VALID 게이트 대상이 아니며, 유지하라는 순차 본문에 따라 상승 에지에서 reset된다.

```text
FAIL: CSR values at 3000: got=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx expected=00000000000000000000000000000000
Fatal: S00-03 register mismatch
FAIL: N=1 reset clears pulses and BRESP at 3000
Fatal: S00-05 policy mismatch
```

즉, **동기 reset 전환과 두 기존 TB의 에지 전 초기화 기대를 동시에 만족할 수 없다.**
기존 검사의 0이라는 값 자체를 바꿀 필요는 없지만, 검사 시점을 reset이 샘플링된 상승 에지 뒤로
옮기는 범위 보정이 필요했다. 최초에는 사용자 명세에 따라 보고했고, 이후 사용자 요청으로
두 검사를 기존 `tick` 뒤로 옮겼다. `tick`은 `@(posedge clk); #1;`이므로 초기 검사는
3 ns 대신 6 ns에 수행한다. reset 자극·유지 시간·기대값·이후 검사 항목은 그대로다.
RTL에 initial이나 추가 payload 게이트를 넣지 않았다.

실패 후 나머지 독립 TB를 계속 실행했다. xsim은 `$fatal` 출력에도 프로세스 exit code 0을
반환했으므로 **종료 코드만으로 PASS 처리하지 않고 FAIL/Fatal 로그를 기준으로 판정했다.**
신규 b-1/b-2와 최초 실패의 관찰 결과는 서로 일관된다. 후속 두 TB 재실행에서
FAIL/Fatal 없이 최종 전체 검사 PASS 문구를 확인하여 완료 조건 2의 **누적 6/6 PASS를 충족**했다.
원래 실패 로그는 8절에, 보정 후 실행 전문은 9절에 보존한다.

## 5. 합성 두 회와 X-01 비교

기존 `syn_check.tcl` / `timing_100mhz.xdc`를 변경하지 않고 각각 1회 실행했다.
아래 두 명령은 `cnn_rtl/syn`에서 설치 경로의 vivado.bat로 호출했다.

```text
vivado -mode batch -source syn_check.tcl -nojournal -nolog -tclargs pose_cnn_v1_0_S00_AXI xc7z010clg400-1 ../rtl/pose_cnn_v1_0_S00_AXI.v
vivado -mode batch -source syn_check.tcl -nojournal -nolog -tclargs pose_cnn_v1_0_M00_AXI xc7z010clg400-1 ../rtl/pose_cnn_v1_0_M00_AXI.v
```

| 대상 | LUT | FF | BRAM | DSP | Setup WNS | 래치 | 조합 루프 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| S00 X-01 기준선 | 182 | 208 | 0 | 0 | +3.895 ns | 0 | 0 |
| S00 R-01 | 183 | 208 | 0 | 0 | +3.895 ns | 0 | 0 |
| 차이 | +1 | 0 | 0 | 0 | 0.000 ns | 0 | 0 |
| M00 R-01 첫 합성 | 364 | 132 | 0 | 0 | +2.779 ns | 0 | 0 |

S00의 reset을 동기식으로 옮기고 RVALID 게이트를 추가한 뒤 총 LUT만 1 증가했다.
FF 개수는 유지됐다. 개별 변경의 자원 기여를 별도 분해한 결과는 아니다.
**S00 임계 경로는 바뀌지 않았다:** `S_AXI_ARESETN` → `S_AXI_ARREADY`, +3.895 ns.
동일 slack의 reset → AWREADY/BVALID 경로도 보고됐다. 기존 READY 게이트 경로가 유지돼
최악의 합성 slack도 동일하게 나온 것이다.

M00 임계 경로는 `M_AXI_ARESETN` → WVALID/전송 성립 논리 → `mem_wr_ready`이다.
`mem_wr_ready = wr_fire = M_AXI_WVALID && M_AXI_WREADY`라는 기존 연결 때문에
추가한 WVALID 게이트가 이 경로에 포함된다. READY 계열에 별도 게이트를 추가한 것은 아니다.

양쪽 모두 `SYN_CHECK_DONE`, exit code 0, Setup failing endpoint 0을 확인했다.
`synth_design` 자체는 오류·critical warning·warning 모두 0이다. 실행 전체에는 다음 메시지가 있다.

- `Common 17-741` CRITICAL WARNING: 로컬 Tcl store `C`의 쓰기 권한 문제로 설치 경로를 사용한다는 환경 메시지.
- `Timing 38-242`: OOC clock port의 HD.CLK_SRC 미지정. 실제 clock buffer 위치·skew는 미확정.
- `Vivado 12-180`: 래치 검색 결과가 비어 발생한 경고. 두 실제 결과는 `LATCH count = 0`.

100 MHz 및 입출력 지연 2 ns는 기존 잠정 제약이다. **WNS는 OOC 합성 추정치**이며
배치·배선/hold/보드 검증은 수행하지 않았다. S00 합성 출력 확인 보조 스크립트의 CRLF 판정은
수정했지만 RTL이나 합성 스크립트를 바꾸거나 S00 합성을 반복하지는 않았다.

## 6. 정적 확인 및 M00 검증 한계

- S00/M00의 변경 전 소스에 허용된 sensitivity·VALID 변경만 적용한 예상본을 만들고,
  주석·공백을 제외한 실제 전체 소스와 대조해 일치했다. 순차 본문·burst·err 정책·나머지 논리는 같다.
- parameter/port 선언은 변경 전후 동일하다. wrapper 연결은 **M00 54/54, S00 32/32**로
  이름·선언 폭이 맞고 외부 AXI 신호 방향도 일치한다. 실제 전체 wrapper 통합 시뮬레이션은 아니다.
- 활성 소스 `cnn_rtl/rtl/**/*.v` 및 프로젝트 루트 직접 위치의 `*.v`에서
  `negedge.*ARESETN`은 0건이다. 루트 M00 사본도 없다.
  보호 대상 템플릿·참고 원본·과거 문서/로그의 비동기 표기까지 제거했다는 뜻은 아니다.
- Top, Encoder 전체 14파일, 도면, 합성 Tcl/XDC, wrapper, CSR 설계 문서·XLSX·인계 문서는
  전후 SHA-256이 같다. 과거 검증 기록도 수정하지 않았다.
- **M00 xvlog 단독 컴파일은 오류·경고 0. 이번 M00 확인은 컴파일·합성·포트/diff 검토뿐이다.**
  M00 기능 TB는 없으며 burst·오류 복구·backpressure의 실제 기능 검증은 T-02에서 수행한다.

민영에게 직접 연락하지 않았다. 원본 위치와 수정 방식 통보 문구는 명세대로 Claude가 작성해
사용자에게 전달할 범위다. D07의 reset 생성·공급 회로와 유지 시간은 이번에 결정하지 않았다.
