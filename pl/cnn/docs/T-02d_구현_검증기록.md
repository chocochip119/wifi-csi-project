# T-02d — M00_AXI 오류·예외 경로 검증

## 2. D08 입력 요약 — 논의에 그대로 사용 가능

### RD_FAULT에 갇히는가 / 탈출 방법

**현 RTL에서 RD_FAULT는 정상 입력만으로 탈출할 수 없으며 reset이 필요하다.** 이른 RLAST와 마지막 RLAST 누락을 각각 주입했고, 상태값 4(`RD_FAULT`) 진입 후 **2,000 cycle 내내 busy=1, err=1**을 확인했다. 그동안 START 1회 재인가와 코어 READY 토글에도 상태·수락 수는 변하지 않았다.

단순히 2,000 cycle 관측만으로 무한 대기를 추정한 것이 아니다. M00 **194행 `RD_FAULT: rd_state_next = RD_FAULT`**를 확인했고, reset 분기(200행 이하)가 IDLE로 복귀시키는 구조다. watchdog도 상태를 바꾸지 않는다. 따라서 `ERR_DRAIN`에서 busy 하강만 기다리는 설계로는 이 상태를 해소할 수 없다. 이 동작은 이번 단계에서 결함으로 판정하거나 수정하지 않았다.

이른 RLAST는 16 beat 중 15개를 받은 뒤 정지해서 마지막 1개가 남았다. 누락은 16개를 모두 받아도 마지막 표시가 없으므로 FAULT에 머물렀다. 두 경우 모두 M00와 슬레이브 모형에 **상승 에지 2개를 포함한 공통 reset**을 주면 IDLE/busy=0/err=0이 됐고, 이후 16 beat 새 read가 정상 완료됐다.

### 오류 후 남은 beat 처리

RRESP/RID/BRESP/BID 오류는 RD_FAULT와 다르게 **정상 종료한다**. 384 B=48 beat=3 burst에서 두 번째 burst에 오류를 주입했는데, 세 번째 burst까지 발행·처리하고 busy가 내려갔다.

- RRESP: 21번째 word에 SLVERR. 이후 **27 word**를 더 받아 총 48개 완료.
- RID: 두 번째 burst의 16개 beat에 잘못된 ID. 첫 오류인 17번째 word 이후 **31 word**를 더 받아 총 48개 완료.
- BRESP/BID: 두 번째 B 응답에서 오류. 당시 32 word를 보낸 상태였고 이후 **16 word/1 burst**를 더 보내 최종 B까지 완료.

주입은 응답 상태/ID를 바꾸며 데이터 자체를 손상시키지 않는 모형 기능이다. 전량 패턴 일치는 전송 순서·drain을 검증한 결과이며, 실제 DDR 오류에서 데이터가 유효하다는 보장은 아니다. busy가 0으로 끝났다는 사실과 실행 성공 여부(err)는 구분해야 한다.

### err clear 시점

**idle에서 START를 수락한 상승 에지 직후에 해당 방향 err가 0으로 지워진다.** START를 에지 사이에서 HIGH로 올리기만 했을 때는 err=1이 유지됐고, 수락 에지의 nonblocking 갱신 뒤 err=0·busy=1을 확인했다. 다음 상승 에지까지 한 cycle 더 기다리지 않는다.

오류 후 idle에서도 5 cycle 이상 sticky가 유지됐다. E1/E2 read의 clear 에지는 각각 66/139, E4 write는 268/397이었다. read START가 write err를 지우지 않는 것도 read-back 중 확인했다. 이 결과는 LOAD의 첫 read 오류를 두 번째 read START 전에 보관·판정해야 한다는 D08 근거다. busy 중 START는 clear 사건이 아니며, RD_FAULT에서도 재START가 err를 해제하지 않았다.

### reset을 전송 중 복구 수단으로 쓸 수 있는가

이번 **공통 reset 시험에서는 가능**했다. read/write 각각 16 beat 중 5개가 수락된 시점에 reset을 걸어 IDLE/busy=0/err=0, reset 중 ARVALID/AWVALID/WVALID=0을 확인했고 새 전송도 완료했다. RD_FAULT에서도 같은 reset으로 복구됐다. 상승 에지 전에는 busy/err 상태가 유지되고, reset이 샘플된 에지 후 초기화되어 동기식 reset 동작도 확인했다.

다만 이번 시험은 **M00와 슬레이브 모형을 함께 reset**했다. 실제 interconnect/DDR이 응답을 보유한 채 M00만 단독 reset하는 복구를 검증한 것은 아니다. 실제 적용에는 reset 범위와 outstanding 거래 처리 계약이 필요하다. 이미 기록된 write 5 word가 reset 뒤에도 남는 것을 확인했으므로 **reset은 메모리 rollback 수단이 아니다.**

### watchdog과 재시작 논의의 연결

WATCHDOG=8은 8회 연속 대기에서 err만 설정하고 **busy/VALID/미완 거래를 취소하지 않았다**. 슬레이브가 다시 응답하면 원래 주소·길이·데이터로 끝까지 처리했다. 영구 무응답을 watchdog 자체가 해결해 주는 구조는 아니다.

이 자료와 기존 Encoder Q3 결과(진행 중 `enc_start` 무시)를 함께 놓고, D08에서 정상 drain 가능한 응답 오류와 reset이 필요한 경우, 부분 데이터 무효화, reset 공급 범위, Encoder 재시작 조건을 논의할 수 있다. **이번 작업은 그 방식이나 우선순위를 확정하지 않았다.**

## 5. 주입과 checker 위반 처리

**모든 case의 예상 checker 코드 = NONE. `expect_violation` 호출은 0회다.** 모형의 C1~C12는 master의 요청·안정성·길이·WLAST·outstanding·reset VALID 등을 검사한다. 모형이 의도적으로 내보낸 잘못된 RRESP/RID/RLAST/BRESP/BID 자체는 그 checker의 master 위반에 해당하지 않으므로 허용 코드를 무장할 이유가 없었다.

| case 묶음 | 모형 주입 수 | 예상 checker 코드 | 허용 근거 |
| --- | ---: | --- | --- |
| E1 RRESP / E2 RID | 각 1 | NONE | 응답 주입과 M00 요청 위반을 분리 |
| E4 BRESP / BID | 각 1 | NONE | 동일 |
| E8 read 오류 / write 오류 | 각 1 | NONE | 동일 |
| E5 early / missing RLAST | 각 1 | NONE | M00의 FAULT 반응 관측. 미완 거래를 완료로 선언하지 않음 |
| E6, E7, E9, 정상·복구 명령 | 0 | NONE | 위반을 예상하지 않음 |

합계 주입 8회, checker 위반 0. 잘못된 RID는 대상 burst 16 beat에 계속 붙지만 모형은 그 주입을 1회로 센다. E5는 FAULT 상태에서 `check_quiescent`를 호출하지 않고, reset 후 별도 정상 복구 case가 끝난 뒤 호출했다. 전송 중 reset 시험도 중단 직전에 quiescent를 선언하지 않았다.

회귀의 **모형 자체시험**에는 원래부터 의도한 master 음성시험 13건/예상 위반 13건이 있다. 이는 기존 자체시험의 성공 조건이며, 실물 M00가 내보낸 위반 0건과 혼동하지 않는다.

## 7. Notion 복사용 요약

> **T-02d 완료 — M00 오류·예외 검증 / D08 근거 확보**  
> 신규 `tb_m00_err.v`로 E1~E9, 22 case 실행. 오류 주입 8회, 실물 M00 프로토콜 위반 0, 허용한 checker 위반 0, reset C12 위반 0. RTL·모형·기존 TB 14파일 해시 보존. 기존 read/write/모형 자체시험 모두 재통과.  
> 중간 burst의 RRESP/RID/BRESP/BID 오류에도 전체 48 beat/3 burst를 처리하고 busy=0. err는 idle에서도 sticky이며 다음 START를 수락한 상승 에지 직후 clear. RLAST 불일치는 RD_FAULT에서 busy=1/err=1로 2,000 cycle 유지됐고 START/READY 변경으로 탈출하지 않음. self-loop 코드와 공통 reset 복구 확인. invalid 4조건은 AXI 없이 busy 1 cycle 후 err. watchdog=8은 8회 대기에 err만 설정하며 AXI를 취소하지 않고 응답 재개 뒤 완료. read/write 동시 진행의 오류 오염 없음. 전송 중 공통 reset 후 새 명령 정상 완료, 이미 쓴 5 word는 유지되어 rollback이 아님.  
> **D08 미결 유지:** 실제 AXI 경로의 reset 범위, FAULT 처리, 부분 데이터 무효화 및 Encoder 재시작 조건은 본 결과로 논의한다. M00 단독 reset의 안전성은 이번 시험 범위가 아니다. Notion 기록은 아직 하지 않았으며 이 요약은 복사용이다.
