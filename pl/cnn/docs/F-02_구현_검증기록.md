# F-02 — FC MAC 구현·golden 누산 검증 완료

2026-09-26. FC1/FC2/FC3의 순수 signed dot product를 계산하는 `fc_mac`을 추가했다. 실제 F-01 FIFO·hidden 버퍼와 Loader FCW RAM을 연결하여 golden 누산값 **128+128+24=280개 전량 일치**를 확인했다. bias는 TB에서만 더했다. FC 제어, requant, GELU 및 core 연결은 F-03 범위로 남긴다.

## 1. 구현 전에 확인한 원문과 보정

원문은 `IP_v1_0/IP_v1_0/interface_spec/Pose_CNN_IP_Interface_Spec.xlsx`의 `08_FC` r46~57과 참고 저장소의 `pl_accel_v6_weight_layout.json`, C++ 누산식이다. 숫자는 실제 blob과 Python 독립 dot product로도 확인했다.

| 레이어 | weight byte offset / 크기 | bias word offset | bias byte offset | FCW 주소 |
|---|---|---:|---:|---|
| FC1 | 5,936 / 393,216 B | 99,788 | 399,152 | FIFO 49,152 word 순차 pop |
| FC2 | 400,688 / 16,384 B | 104,268 | 417,072 | 0~2,047 |
| FC3 | 418,608 / 3,072 B | 105,420 | 421,680 | 2,048~2,431 |

- **FC3 tag 표기 보정:** 작업 명세 Z3의 `{2'b10, o[4:0]}`는 7-bit다. 원문 r57과 완료 조건에 맞춰 **9-bit `{mac_sel_latched[1:0], out_idx[6:0]}`**를 사용했다. FC3의 유효 tag는 `0x100~0x117`이다.
- **INT8 최대 곱 보정:** 최댓값은 127²=16,129가 아니라 **(−128)²=16,384**다. FC1 최대 순수 합은 **50,331,648**, 최소는 **−49,938,432**다. 8개 곱의 합에는 signed **19-bit**를 사용했다.
- **hidden 주소 정합:** 원문 r51은 `{bank, word[3:0]}` 5-bit packed 주소다. MAC은 이 형식을 출력한다. F-01의 hidden 버퍼는 별도 bank 입력과 bank 내부 주소를 받으므로 TB/합성 fixture에서 `.hidden_rbank(hidden_raddr[4])`, `.hidden_raddr({1'b0, hidden_raddr[3:0]})`로 연결했다. 기존 hidden RTL 변경 없음. **F-03에서도 이 분리가 필요하다.**
- **384/16/16 간격의 조건:** 무정체 공급에서 검사한다. FIFO가 비면 주소 발행을 멈추므로 FC1 간격이 늘어난다. 정체 시험에서는 각 출력의 마지막 입력 발행 시각을 기록하고 파이프라인 지연과 전량 수치를 함께 대조했다.
- reset은 원문 구버전의 비동기 문구 대신 사용자 확정 공통 계약인 동기식 active-low를 적용했다.

### 상태와 주소

`IDLE → ISSUE → DRAIN → DONE → IDLE`이다. 여기서 DRAIN은 남은 산술 파이프라인을 처리하는 MAC 내부 상태이며 Top의 오류 ERR_DRAIN과 무관하다. IDLE에서 `mac_start`를 수락해 `mac_sel`을 보관한다. 진행 중 start는 무시한다. 예약 선택값 3의 start는 수락하지 않는다.

- FC1: `flat_raddr=word_idx`(0~383 반복), `fifo_re=issue && sel==0`. FIFO가 비면 issue와 카운터 진행을 모두 멈춘다.
- FC2/3: hidden 주소는 `{sel==2, word_idx[3:0]}`, FCW 주소는 `{sel==2, out_idx[6:0], word_idx[3:0]}`다. 이는 FC2 `o*16+j`, FC3 `2048+o*16+j`와 같다.
- 주소는 조합으로 발행하며, 입력을 받아들인 edge에만 word/output 카운터가 진행한다. 출력 첫 word에는 누산을 새로 시작하고 마지막 word에는 `acc_valid`와 tag를 낸다.
- `mac_done`은 최종 `acc_valid` 다음 cycle에 1-cycle로 나온다. 이는 **MAC 결과 완료** 신호이며, F-03의 requant/GELU 및 버퍼 저장 완료를 뜻하지 않는다.

### 읽기 지연과 파이프라인

입력 word를 발행하는 상승 edge를 **E**라고 하면:

| Edge | 동작 |
|---|---|
| E | RAM이 읽기 주소를 샘플링. FC1은 FIFO head를 보관하면서 pop |
| E+1 | RAM 활성값과 같은 word의 weight를 operand 레지스터에 함께 보관 |
| E+2 | signed 8×8 곱 8개 → 각각 16-bit |
| E+3 | 곱 2개씩 합 → signed 17-bit 4개 |
| E+4 | 합 2개씩 합 → signed 18-bit 2개 |
| E+5 | 8개 곱의 총합 → signed 19-bit |
| E+6 | sign extension 후 signed 32-bit 누산. 출력 마지막 word이면 acc_valid |

valid와 `{first_word, last_word, last_layer_word, tag}`를 같은 단계로 이동한다. FIFO가 비면 새 입력 발행에만 공백을 넣고 이미 받은 데이터는 계산을 끝낸다. TB는 출력마다 **마지막 word 발행+6 cycle**에 결과가 나오는지 검사했다. 8개 곱셈과 모든 덧셈은 명시적으로 나열했으며 `for/task/function/initial/generate/genvar`는 RTL에 없다. DSP 속성 강제 없음.

## 4. Z1~Z3 — golden 280개 전량 일치

시작 수락 상승 edge를 cycle 0으로 측정했다. FC2/3 활성값은 실제 hidden 버퍼의 각 bank에 쓰고 읽었으며, weight도 실제 `fcw_ram`에 적재했다. FC1에는 실물 512×64 FIFO를 사용했다.

| 레이어 | 입력 word / 출력 | 불일치 | acc_valid 간격 | 첫 acc | 마지막 acc | mac_done | tag 범위 |
|---|---|---:|---:|---:|---:|---:|---|
| FC1 | 49,152 / 128 | **0** | **384** | 390 | 49,158 | 49,159 | 0x000~0x07F |
| FC2 | 2,048 / 128 | **0** | **16** | 22 | 2,054 | 2,055 | 0x080~0x0FF |
| FC3 | 384 / 24 | **0** | **16** | 22 | 390 | 391 | 0x100~0x117 |

비교식은 항상 **signed 64-bit TB 계산의 `MAC.acc + blob_bias[o]`**다. golden이 bias를 이미 포함한다는 점을 확인했고, MAC에는 bias를 더하지 않는다. 각 출력·tag·cycle을 전부 확인한다. 불일치 시 TB가 처음 5개 `(case, output index, golden/expected, 우리 acc+bias, pure acc, bias)`를 출력하며, 현재 불일치는 0개다.

FC3의 이번 모델/입력 결과는 모두 양수다. 이를 숨기지 않으며 FC1/FC2의 **176개 음수 출력**으로 실제 데이터 signed 동작을 확인했다. 추가로 FC1 전체 활성값을 −128로 채우고 실제 FIFO로 아래 두 극값을 공급했다:

| 활성/weight | 출력 128개 각각의 결과 | 이론값과 불일치 | 가까운 INT32 경계까지 여유 |

## 6. Z5/Z6 — 정체·제어·공허 통과 방지

FC1 무정체 시험은 먼저 실제 FIFO를 512개로 채워 full을 발생시켰고, 생산자가 막힌 full cycle **5회**, overflow **0**을 관측했다. 그 후 매 cycle 공급해 384-cycle 출력 간격을 확인했다.

정체 시험은 seed `FC020123`에서 이어지는 재현 가능한 xorshift 공급과 긴 공급 중단을 사용한다. **7,351 cycle** 동안 FIFO empty로 MAC 주소 발행이 멈췄다. 49,152개 weight 모두 순서대로 소비했고, 128개 golden 누산값이 다시 전량 일치했다. 완료는 **56,510 cycle**, 무정체 대비 정확히 **7,351 cycle 증가**했다. 출력 간격이 늘어난 구간은 126개다.

empty 상황에 TB가 FIFO read 입력을 시험용으로 올린 **7,358회**에도 FIFO 읽기 포인터가 변하지 않았다. MAC 자체는 empty일 때 fifo_re를 내지 않았다. probe 횟수에는 입력 수신 완료 후 산술 파이프라인을 마무리하는 7 cycle도 포함된다.

모든 12 case에서 `mac_sel`을 start 후 다른 값으로 바꾸고, 진행 중 `mac_start`를 1회 다시 넣었다. 모두 처음 선택된 레이어를 끝냈다. 완료는 마지막 valid 다음 cycle에 정확히 1-cycle이며 이후 idle 출력이 유지된다. case 사이 별도 reset 없이 재시작하여 이전 레이어의 파이프라인 상태가 다음 레이어에 섞이지 않음도 확인했다.

공허 통과 방지는 세 레이어 모두에서 활성 한 byte와 weight 한 byte를 **각각 별도 case**로 바꿨다. 단지 출력이 다른지 보지 않고, 원래 golden에 `변화량 × 대응 weight/activation`을 더한 독립 기대값과 모든 출력을 대조했다.

| 레이어 | 활성 변경 | 달라진 출력 수 | weight 변경(레이어 내부 byte index) | 달라진 출력 수 |
|---|---|---:|---|---:|
| FC1 | byte0 +1 | **126** | byte15,360 +1 (출력5의 입력0) | **1** |
| FC2 | byte0 +1 | **127** | byte640 +1 (출력5의 입력0) | **1** |
| FC3 | byte0 +1 | **24** | byte640 +1 (출력5의 입력0) | **1** |

기본 실행 **12 case / 결과 1,224개 / assertion 2,128,172건 / 320,872 cycle**, 불일치 0. 1,224개에는 baseline 280개, 정체 128개, 변형 560개, 극값 256개가 포함된다. baseline golden 280개와 추가 검증 수량을 구분한다.

## 7. Z7 — 합성

Vivado 2020.2, `xc7z020clg400-1`, 기존 100 MHz OOC·입출력 delay 2 ns 제약. 기존 `syn_check.tcl`/XDC 무변경. 합성 후 `check_timing -verbose`, LUTLP-1 DRC도 확인했다.

| 구성 | LUT (중 LUTRAM) | FF | RAMB36 / 18 | DSP | WNS | 래치 / 조합 루프 | wall-clock |
|---|---:|---:|---|---:|---|---|---|
| fc_mac 단독 | **799 (0)** | **616** | 0 / 0 | **0** | **+3.895 ns** | 0 / 0 | 50.382 s |
| MAC + FIFO/hidden/pose | **955 (64)** | **965** | **1 / 0** | **0** | **+3.857 ns** | 0 / 0 | 31.309 s |

DSP를 강제하지 않았고 Vivado는 8개 INT8 곱을 LUT로 구현했다. 묶음의 FIFO는 RAMB36E1 1개, hidden은 RAM32M 16개, pose는 FF 192개로 유지됐다. FCW RAM은 Loader 소유이므로 **합성 묶음에서는 외부 읽기 인터페이스로 유지**했다. 기능 TB에서는 실물 FCW RAM을 사용했다. Pose 쓰기는 합성 fixture 외부 입력으로 보존하여 최적화로 사라지지 않게 했으며, requant/GELU를 구현한 것이 아니다.

단독 임계 경로는 `fifo_empty → fifo_re`, 데이터 지연 2.070 ns, LUT4 한 단계다. 묶음은 `u_fifo/count_reg_reg[9]/C → fifo_full`, 데이터 지연 3.135 ns, LUT3/LUT5 두 단계다. **두 WNS 모두 중단 기준 +1.0 ns 이상**이다. P&R/코어 전체/FC 후처리 타이밍 결과가 아니다.

합성 오류 0. 기존 Common 17-741(Tcl store), Timing 38-242(OOC clock skew), Vivado 12-180(검색 결과 없음) 외에 MAC 단독에서 Netlist 29-101(flat primitive 수가 많아 floorplanning에 비이상적) 안내가 있었다. 시뮬레이션 compile/elaboration 경고와 구분해 보존한다.

MAC은 bias 없는 합만 출력하고 TB가 실제 blob bias를 더해 golden 280개 전량 일치를 확인했다. 출력 간격 384/16/16 cycle, tag 9-bit, mac_done은 마지막 acc_valid 다음 cycle의 1-cycle 펄스. FIFO empty 7,351 cycle 정체 후에도 weight 49,152개와 결과 128개 전량 일치. 세 레이어의 활성/weight 한 byte 변형 및 INT8 극값 시험 통과. 기존 23 TB 무수정 통과, 보호 파일 389개 SHA-256 무변경. MAC 단독 LUT799/FF616/DSP0/WNS +3.895 ns, 저장소 묶음 LUT955/FF965/RAMB36 1/DSP0/WNS +3.857 ns, 래치·조합 루프 0. F-03 requant/GELU·FC 제어는 미착수.

다음 단계 제목: **F-03 — FC 제어 + requant/GELU 결합 + pose 출력**. requant의 FC 대응 A/B 선택과 GELU tag/LUT table 정합 확인이 남아 있다. `mac_done`을 FC 전체 완료로 바로 연결하지 말고 후처리/저장 완료를 기다려야 한다.
