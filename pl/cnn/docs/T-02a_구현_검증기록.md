# T-02a — AXI4 슬레이브 메모리 모형·프로토콜 검사기·자체 시험

날짜: 2026-09-25. **구현·자체 시험 완료 / Claude 검수·사용자 확인 대기.**

Vivado 2020.2에서 두 신규 파일을 `xvlog -sv` → `xelab` → `xsim -runall`로 확인했다.
컴파일·elaboration 오류/경고는 0건이며 A/B/C/D 그룹이 모두 통과했다.
필수 음성 시험 6/6, 추가 시험까지 13/13건이 각각 지정한 위반을 정확히 1회 검출했다.
같은 seed로 자체 시험 전체를 다시 실행해 PASS/EXPECTED_VIOLATION 49줄이 시각까지 동일함을 확인했다.
별도 fatal 시험에서는 미허용 위반과 1회 허용 뒤 재발한 위반 모두 실제로 종료시켰다.

## 1. 목적·변경 범위

후속 M00 검증에서 메모리 응답, 지연, backpressure, 잘못된 응답을 재현하는 독립 TB 부품이다.
모형의 저장 기능과 검사기 자체를 먼저 시험하여 후속 실패 원인을 구분할 수 있게 했다.

| 신규 소스 | 역할 |
| --- | --- |
| [axi4_slave_mem_model.v](../testbench/axi4_slave_mem_model.v) | 희소 메모리, AXI slave 5채널, 실행 중 흐름 제어, 1회 오류 주입, C1~C12 검사기 |
| [tb_axi4_slave_mem_model.v](../testbench/tb_axi4_slave_mem_model.v) | 간단한 절차형 마스터, 독립 예상 데이터, A/B/C/D 자체 시험, R/B 안정성 감시 |

기존 RTL 3개와 기존 TB 6개는 SHA-256 전후 일치로 보존을 확인했다.
M00은 include/instantiate하지 않았으며 실행 명령에도 두 신규 파일만 들어간다.
두 소스 첫 줄은 모두 `` `timescale 1ns / 1ps ``이다. 합성 및 기존 6TB 회귀는 이번에 실행하지 않았다.
결과 문서와 공통 문서의 현재 단계만 함께 정리했다.

근거: 사용자 T-02a 명세의 `03_M00_AXI r27~r65/r70~r73` 계약과 실제 M00 포트 선언,
`PROJECT_CONTEXT.md` 4절/5.2절. RTL 기능이나 공통 인터페이스를 변경하지 않았다.

## 2. 저장·흐름 제어·오류 주입 사용법

저장소는 `(byte_addr >> 3)`를 key로 하는 연관 배열이다. AXI W는 최대 16 beat 임시 버퍼를 쓰지만,
주소 공간의 메모리 배열에는 고정 깊이 제한이 없다. 쓰지 않은 word는 `64'hDEAD_BEEF_BAD0_0001`이다.
`mem_word(addr)`는 word를 반환하고, `mem_fill(addr, bytes, seed)`는 패턴을 채우며,
`mem_compare(addr, bytes, seed, mismatches)`는 불일치 word 수를 반환한다.
fill/compare 범위는 8-byte 정렬·8의 배수 길이여야 한다.

패턴은 `{seed ^ 32'hA5C39E71, byte_addr ^ seed}`다. 같은 seed에서 주소가 달라지면 값도 다르다.
자체 시험의 예상값은 TB에서 별도로 계산하며 모형의 패턴 함수를 호출하지 않는다.
fill 320 B를 16+16+8 beat로 읽고, 정상 compare=0 및 잘못된 seed compare=1도 확인했다.

| 공개 설정 | 의미 |
| --- | --- |
| `ar_ready_mode / aw_ready_mode / w_ready_mode` | 0: 수락 가능한 동안 READY, 1: 주기 수락, 2: xorshift32 난수 |
| `ar_gap_cycles / aw_gap_cycles / w_gap_cycles` | mode 1의 READY 기회 간격=`gap+1` clocks. 0이면 매 clock |
| `ar_seed / aw_seed / w_seed` | 방향별 독립 PRNG 상태. 재현하려면 같은 seed와 같은 자극/클록 순서를 사용 |
| `r_gap_cycles` | 앞 R beat 수락 뒤 다음 beat까지 삽입하는 빈 cycle 수 |
| `ddr_latency_cycles` | AR 수락 뒤 첫 RVALID 생성까지 추가 지연 |
| `b_delay_cycles` | WLAST 수락부터 BVALID 생성까지 추가 지연. AW 수락도 반드시 필요 |
| `check_outstanding` | 기본 1. C11 검사만 켜고 끔. 0이어도 모형의 처리 능력은 방향당 1 burst |
| `write_timeout_cycles` | 기본 0(비활성). 시험자가 명시한 W 부족 판정 deadline |

READY mode·gap 및 세 지연 기본값은 모두 0이다. mode 0도 진행 중인 burst/응답·버퍼 용량에 따른
backpressure는 적용된다. 설정은 falling edge에서 바꾸며 음수 gap/지연은 지원하지 않는다.
PRNG는 해당 mode=2인 매 정상 상승 에지마다 전진한다. seed=0은 내부 계산에서 1로 치환한다.

지연의 기준을 구분한다. 지연 0이면 AR/WLAST를 수락한 에지 직후 RVALID/BVALID를 구동할 수 있고,
READY=1일 때 **첫 응답 handshake는 다음 에지, 즉 1 clock 뒤**다. 따라서 지연 L의 시험 관측치는 L+1이다.
R gap=G이면 연속 handshake 사이가 G+1이다. AW가 늦으면 AW도 기다리지만 이미 지난 WLAST 지연을
AW부터 다시 세지 않는다. 이 값들은 시험 모형의 제어값이며 실제 DDR 지연을 확정한 것이 아니다.

AW와 W는 독립 수락한다. 예를 들어 W 4개가 먼저 오면 임시 버퍼에 보관하고,
AW가 오기 전까지 메모리 갱신과 BVALID를 보류한다. AW가 수락되면 주소에 맞게 버퍼를 반영하며,
AW와 WLAST가 모두 수락되고 beat 수가 일치한 경우에만 B 응답을 낸다.
읽기와 쓰기는 동시에 진행할 수 있고, R/B payload는 READY를 기다리는 동안 고정한다.

| 오류 요청 | 적용·자동 해제 | 실제 발생 카운터 |
| --- | --- | --- |
| `inject_rresp`, `inject_rresp_beat` | 다음 AR에서 snapshot 후 요청 해제. 지정한 0-based beat만 RRESP 변경 | `rresp_injected` |
| `inject_rid` | 다음 read burst의 RID=1, 그 다음 burst는 0 | `rid_injected` |
| `inject_bresp` | 다음 AW에 해당하는 B 응답 변경 | `bresp_injected` |
| `inject_bid` | 다음 AW에 해당하는 BID=1 | `bid_injected` |
| `inject_rlast_mode` | 0 정상 / 1 끝에서 한 beat 이른 위치 / 2 RLAST 없음 | `rlast_injected` |

early RLAST에는 최소 2 beat가 필요하다. 두 RLAST 오류 모드 모두 ARLEN+1개 데이터는 계속 제공하며,
RLAST 표식만 바꾼다. 실제 마스터가 잘못된 RLAST를 보고 멈추면 모형도 READY를 기다린다.
복구 정책은 후속 실물 시험 범위다.

카운터는 요청 시점이 아니라 오류 payload를 처음 VALID로 **구동한 시점**에 증가한다.
fault 종류별 burst당 1회이며, stall 중 같은 payload를 반복 표시해도 늘지 않는다.
`injection_count`는 종류별 합계다. 동기 reset은 진행 중 거래와 미사용 주입 요청을 지우지만
메모리, 설정·seed, 누적 주입/위반 카운터는 보존한다. 요청만 한 뒤 reset한 시험에서 발생 수가
늘지 않는 것도 확인했다.

## 4. C1~C12 검사 위치와 판정

기본 `protocol_error(code,msg)`는 `$fatal`로 멈춘다.
`expect_violation(code)`는 지정된 code의 다음 위반 1건만 세고 즉시 해제한다.
다른 code, 두 번째 위반, 중첩 arm은 허용하지 않는다. 시험 종료에 `check_quiescent()`를 호출하면
미소모 기대 위반이나 끝나지 않은 거래도 실패 처리한다.

| 규칙 | 구현 내용 | 모형 코드 위치 | 자체 시험 |
| --- | --- | --- | --- |
| C1 | AR VALID·payload stall 유지 | [264행](../testbench/axi4_slave_mem_model.v#L264) | D1 |
| C2 | AW VALID·payload stall 유지 | [266행](../testbench/axi4_slave_mem_model.v#L266) | 추가 AWVALID 조기 해제 |
| C3 | W VALID·payload stall 유지 | [268행](../testbench/axi4_slave_mem_model.v#L268) | 추가 WDATA 변경 |
| C4 | SIZE=3 / BURST=INCR / ID=0 | [207행](../testbench/axi4_slave_mem_model.v#L207) | D2 |
| C5 | LEN≤15 | [208행](../testbench/axi4_slave_mem_model.v#L208) | D3 |

| C12 | reset 중 master VALID=0 | [235행](../testbench/axi4_slave_mem_model.v#L235) | 추가 reset 중 AWVALID 및 정상 게이트 |

C1~C3은 READY가 마지막으로 올라오는 에지까지 이전 payload와 VALID를 확인한다.
AR/AW의 LOCK/CACHE/PROT/QOS도 안정성 벡터에 포함했다. C4~C7은 AR/AW 수락 시 공통 검사한다.
WSTRB는 AW 이전에 수락한 W에도 적용하며 WLAST는 AW가 온 뒤 선행 버퍼 내용까지 대조한다.

**C10의 부족 판정:** AXI에는 W 도착 최대 시간이 없으므로 조용한 몇 cycle만으로 부족을 단정할 수 없다.
자동 시간 제한은 기본 비활성이고, 자체 시험에서는 `check_quiescent()`로 시험 종료를 명시해
AWLEN+1보다 적은 beat를 검출했다. 필요한 시험만 `write_timeout_cycles`를 지정할 수 있다.
초과는 수락된 W 수량으로 즉시 검출한다. C10의 수량 오류와 C9가 겹치면 수량 오류를 우선 진단한다.

C11은 이번 프로젝트의 방향당 1 outstanding 계약이다. 이전 응답 완료 전 **새 주소를 제시하는 것**을
검사한다. 스위치를 끄면 새 VALID를 일찍 제시할 수 있지만 READY가 직렬화하며 다중 outstanding 구현은 아니다.
C12는 clock 사이 위반도 감시하되 `#0` delta settling 뒤 판정한다. 정상 master의 조합 reset 게이트가
같은 시각에 갱신되는 과정을 오검출하지 않도록 했고, 정상 게이트와 실제 reset 중 위반을 모두 시험했다.
이 감시는 TB 검사기이며 비동기식 상태 reset 회로를 추가한 것이 아니다.

음성 시험 뒤에는 reset으로 잘못된 거래를 정리한다. 예상 위반을 1회 허용하는 기능은 오류 거래 복구 모델이 아니다.

두 번째 AR(C11), clock 사이 reset 중 AWVALID(C12). 각각 증가량 1로 총 **13/13 PASS**다.

### 별도 fatal 동작 확인

- `FATAL_UNEXPECTED`: arm 없이 C4 위반 → `unexpected AXI master violation`으로 실제 종료.
- `FATAL_ONESHOT`: 첫 C4는 `expect_violation(4)`로 1회 기록, 다음 C4는 실제 종료.
- 이 두 실행의 `FAIL:`/`Fatal:`은 **의도한 종료를 증명하는 출력**이다. 정상 자체 시험의 실패가 아니다.
- xsim은 `$fatal`에도 프로세스 종료 코드 0을 반환할 수 있으므로 종료 코드만으로 PASS 처리하지 않았다.
  정확한 fatal 메시지, 기대 위반 횟수, 정상 완료 문구의 부재를 확인했다.

DDR 지연값, outstanding 확대, D06/D08/D09/D10 및 D07 공급 구현은 이번에 확정하지 않았다.
