# WiSensing PC Frontend

Windows에서 더블클릭으로 Backend+Frontend를 자동 실행하려면 **[원클릭 실행 가이드](../../docs/oneclick_launcher.md)**의 `WiSensing_Start.bat`를 사용하세요. 브라우저 화면의 종료 버튼은 이 실행기로 시작했을 때에만 활성화됩니다.

Three.js/Vite 기반 위치·12관절 시각화 UI입니다. **위치 추론은 Zynq PS의 C Ridge**, 자세 추론은 **FPGA PL의 CNN**이 수행합니다. PC Backend는 TCP 5000 결과를 수신·검증·통합하고 Frontend에 HTTP/WebSocket으로 전달합니다.

## 위치별 캐릭터 동작과 안정화

| 위치/상태 | 화면 동작 |
|---|---|
| **위치 모드 (`3`으로 전환)** | P01~P09로 걸어가며, 이동 중 2D 걷기 스켈레톤/3D Walk, 도착 후 기본 서기; P10은 중앙의 앉기 표시. 팔·다리 실시간 추종은 이 모드에서 적용하지 않음 |
| **모션 모드 (`3`으로 전환)** | 캐릭터를 **P05에 고정**, 추정 구역(P01~P10)과 독립적으로 실제 12관절 팔·다리·스쿼트를 시각화 |
| **위치 불명·유효하지 않음** | 새 추정 위치를 임의로 만들지 않으며, 위치 모드의 캐릭터/관절 표시는 중립 자세 |
| **모션 모드 명시적 사람 없음** | 기존 자세를 최대 5초 유지하다 캐릭터와 스켈레톤 숨김(미수신/오래된 결과를 자동으로 사람 없음으로 판단하지 않음) |

원본 관절 좌표는 변경하지 않으며, **화면의 3D/2D 표시 정책**으로만 걷기·서기·동작을 선택합니다. 모션 모드의 스쿼트/다리 들기는 양쪽 **무릎(25/26), 발목(27/28), 골반(23/24)**의 2D 기하를 비교합니다. 일반 스쿼트 시작은 **새 관절 프레임 2개**, 보통 다리 들기 시작도 **2개**(매우 뚜렷한 한쪽 다리 들기는 1개), 최소 유지 **650ms**, 스쿼트↔다리 들기 직접 전환은 **4개**, 앉기 해제는 **5개**를 적용합니다. 위치 모드의 비-P10 앉기 기하 판정도 관절 프레임 **2개**를 확인하고, P10은 Backend에서 이미 안정화한 위치 결과로 사용합니다. 이 수치는 **Backend의 위치 확정 2회와 서로 다른 규칙**입니다.

## 화면 구성과 구현 기능

| 화면·기능 | 사용자에게 보이는 내용 | 처리 방식 |
|---|---|---|
| **메인 3D 공간** | 공간 내 3D 캐릭터 이동·서기·앉기·팔·다리 동작 | Three.js 장면과 캐릭터 본/IK |
| **2D POSE RESULT** | 12관절을 연결한 스켈레톤과 자세 정보 | FPGA CNN에서 전달받은 24개 좌표 표시 |
| **LOCATION RESULT** | P01~P09 구역, P10(중앙 앉기), 사람 없음 | Backend Location 결과 표시 |
| **위치/모션 보기** | 실제 구역에 따라 움직이는 보기 ↔ 중앙 P05 고정 자세 보기 | 키보드 **3**으로 전환 |
| **좌우 동작 보정** | 사용자 눈에 보이는 관절 좌우가 반대일 때 즉시 전환 | 메인 화면 **좌우 반전 ON/OFF** 버튼 (2D·3D 동시) |
| **미감지·상태 처리** | 연결 상태 및 사람 없음 시 화면 표시 | 모션 보기에서는 연속 5초 미감지 후 관절·캐릭터 숨김 |
| **관리자·테스트 창** | RX 배치/연결, 관절 입력, Pose 테스트, 기록 재생·성능 확인 | `integration.html`에서 별도 설정 |
| **기록 재생** | JSON/JSONL 및 지원되는 기록 데이터를 다시 재생 | 저장된 스냅샷·관절로 시각화 |

### 데이터가 화면에 보이기까지

```text
PS → PC Backend (위치/관절 상태)
            ↓ HTTP / WebSocket
         Frontend
          ├→ 2D 관절 스켈레톤
          ├→ 3D 캐릭터 (관절 추종 + 발/무릎 IK)
          └→ 9구역 위치 및 상태 표시
```

2D 관절을 바탕으로 3D 캐릭터가 움직이는 **시각화**이며, 2D 입력에 없는 깊이 정보는 제한된 본/IK 규칙으로 보완합니다. 화면의 좌우 전환, 자세 안정화·다리 제한은 **Frontend에만 적용**되어 Backend의 CNN 원본 12관절 좌표를 바꾸지 않습니다.

## 실행

저장소 루트에서 Windows PowerShell:

```powershell
cd pc\frontend
npm ci
npm run dev
```

브라우저:
- 시연: http://localhost:5173/
- 실제 연결 상태 및 RX 확인: http://localhost:5173/integration.html

별도 터미널에서 Backend를 실행합니다. 둘 중 한 모드만 선택합니다:

```powershell
# UI 테스트 전용 (실제 하드웨어/위치 정확도 검증 아님)
python pc\backend\run_backend.py --fake

# 실제 Zybo: 주소는 보드의 실제 IP로 변경
.\scripts\start_backend_real.ps1 -PsIp 192.168.10.2
```

Frontend는 기본적으로 같은 호스트의 Backend HTTP 8000과 WebSocket /ws를 이용합니다.
Vite WebSocket 연결 주소는 VITE_BACKEND_WS_URL 환경 변수로 설정할 수 있습니다(변경 후 Vite 재시작).
진단 페이지는 다음처럼 다른 Backend 주소를 지정할 수 있습니다:

```text
http://localhost:5173/integration.html?backend=http%3A%2F%2F192.168.10.100%3A8080
```

## 로컬 3D 캐릭터 파일

UI는 /public/models/Male01.gltf, Male02.gltf, Female01.gltf, Female02.gltf를 로드합니다.
해당 모델 및 텍스처는 배포 라이선스가 확인되지 않아 GitHub 저장소에 포함되지 않습니다.
사용 권한이 있는 모델과 그 종속 텍스처를 직접 pc/frontend/public/models/에 배치해야 캐릭터가 표시됩니다.

## 실제 RX 배치 확인

1. Zybo의 통합 `pose_cnn_rx5_live`가 **TCP 5000 하나**에 PS Location(type 5)·FPGA Pose(type 2)·STATUS/ACK를 제공해야 합니다. TCP 5001은 과거 분리판의 포트입니다.
2. integration.html에서 RX0~RX4의 MAC, 슬롯, saved order, 실제 물리 배치가 학습 당시와 맞는지 직접 확인합니다.
3. 체크 후 추론 시작을 누르면 화면에 표시된 RX 구성 서명(rx_signature)을 서버로 전송합니다.
4. Backend는 TCP 연결, 10초 이내 STATUS, RUN/RX5 connected/live/saved, 모델의 MAC/무선 설정, 확인 서명 일치를 검사합니다.
5. 이후 위치 엔진이 다음 STATUS를 재검증하여 추론을 시작합니다. 연결/배치가 바뀌면 다시 확인해야 합니다.

수동 API 사용 시 현재 서명을 조회한 다음 직접 대조하고 전달합니다:

```powershell
$layout = Invoke-RestMethod http://127.0.0.1:8000/api/rx-layout
$layout
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/confirm-rx-layout -ContentType 'application/json' -Body (@{rx_signature=$layout.rx_signature} | ConvertTo-Json)
```

## LIVE/TEST 화면 설정

시연 페이지 오른쪽 상단의 **⚙ 관리자 · 관절 테스트** 버튼을 누르면 **별도 브라우저 설정 창**이 열립니다. 위치·12관절 그림·3D 모션을 각각 독립적으로 제어하고, 변경을 메인 3D 화면에 즉시 반영합니다. 팝업이 차단된다면 해당 사이트의 팝업을 허용하세요.

| 설정 | LIVE | TEST / OFF |
|---|---|---|
| 위치 | Backend의 실제 P01~P10 분류 | P01~P09 수동 지정, P10 수동 앉기 |
| 12관절 그림 | FPGA의 실제 12관절 | 서기/팔 올리기/팔 벌리기/스쿼트/다리 들기 샘플 또는 숨김 |
| 3D 모션 | FPGA 관절을 캐릭터 리그에 반영 | 동일 샘플 모션 또는 기본 서기·앉기 |

- **P05와 P10은 같은 중앙 Zone 5**입니다. P05=서기, P10=앉기이며 양쪽 모두 12관절 표시·모션을 선택할 수 있습니다.
- P10의 앉기 표현은 현재 **관절 기반 본/IK 보정**을 중심으로 구성합니다. 모델별 애니메이션·리그 차이에 따라 자연스러움이 달라질 수 있어 실제 GLTF 화면에서 확인합니다.
- 실제 팔·다리 추종 **모두 기본 ON**. 동일한 FPGA 12관절 좌표를 스켈레톤과 3D 모션에 입력합니다. 2D 입력 기반 다리 IK는 실험적이므로 화면에서 좌표/동작을 비교하며 개선할 수 있고, 필요할 때 설정창에서 다리 추종을 OFF로 바꿀 수 있습니다.
- 수동 위치 및 샘플 관절/모션은 프론트 화면만 바꾸며, FPGA/Backend 추론 데이터나 RX 확인 상태를 변경하지 않습니다.
- 모든 항목을 실제 추론으로 되돌릴 때는 **전체 LIVE** 버튼을 누릅니다.
- 저장한 JSON/JSONL 재생은 키보드 **O**, 실시간 복귀는 **B**, 관절 좌우 보정 모드는 **M**으로 유지됩니다.
실제 CNN 좌표는 INT8 × output_scale 결과인 model_output 좌표이므로 정규화된 0..1 좌표로 가정하지 않습니다.

추가 자료: [통합 실행 순서](../../docs/bringup.md), [PS README](../../ps/README.md), [Backend README](../backend/README.md).



## 3D 다리 동작과 앉기 판정

- **모션 모드에서는 추정 위치가 P01~P10 중 어디든 캐릭터가 P05에 고정**되며, 실제 관절 추종과 다리 들기에 위치별 제한을 걸지 않습니다. 위치/모션 표시 정책을 서로 분리했습니다.
- `legLiftPolicy.js`에 다른 구역의 **10° 시각화 제한**이 남아 있지만, 현재 위치 모드는 실시간 다리 관절 추종 자체를 하지 않으므로 일반 위치 보기의 동작 규칙으로 설명하면 안 됩니다. 10°도 실제 측정 3D 고관절 각도가 아닌 화면 보정값입니다.
- 들린 발만 약하게 바깥쪽으로 돌리고 지지발은 기존 방향을 유지합니다. **모션 모드에서 P10 예측만으로 강제 앉기를 만들지 않으며**, 한쪽 다리 들기는 기하 근거로 구분합니다(원본 위치 분류 결과는 그대로 표시).
- 앉기는 기존 양발 지지 IK를 사용하고, 실제 장비에서는 분류 변동과 시각화를 확인해야 합니다.

## 위치/모션 보기와 미감지 처리

메인 화면의 모드 선택 버튼은 제거되었습니다. 위치 확정은 Backend의 서로 다른 PS 윈도우 2회 연속 확인이며, 이 화면의 스쿼트 프레임 안정화와는 독립적입니다. 키보드 **3**을 누를 때마다 **위치 모드(P01~P10 따라가기) ↔ 모션 모드(P05 중앙 고정)**로 바로 전환됩니다. 모션 모드에서는 **명시적인 사람 없음 상태가 연속 5초 이상** 지속되면 화면의 스켈레톤과 3D 캐릭터를 숨기며, 그 전에 사람이 다시 감지되면 타이머가 초기화됩니다. 화면의 **↔ 좌우 반전 ON/OFF** 버튼을 누르면 2D 스켈레톤과 3D 캐릭터의 좌우 동작을 **함께** 변경할 수 있습니다(기본값 ON). 표시는 12관절의 X 좌표 반전과 좌우 관절 쌍(어깨·팔꿈치·손목·골반·무릎·발목) 교환을 공통으로 적용합니다. 입력 CNN 좌표, Backend/FPGA 추론 결과는 변경하지 않으며, GLTF 모델의 X축 음수 스케일은 사용하지 않습니다. 실제 위치 결과와 Pose 데이터는 두 모드 모두 계속 수신하고, 별도 설정 팝업에서 기존 고급 설정을 사용할 수 있습니다.

`/integration.html` 관리자는 CSI/POSE 연결, RX 배치, 실제 위치·Pose 결과, 각 추론시간과 데이터 경과, 원본 12관절 좌표를 표시합니다. 처음 설치한 PC에서의 실행 순서는 [구동 PC 설치·운영 가이드](../../docs/wisensing_live_v18_operator.md)를 참고하세요.


## 관리자 화면과 관절 편집

상단 **⚙ 관리자 · 관절 테스트** 버튼으로 `/integration.html`을 엽니다. 이 화면에서 RX·추론시간 확인 및 관절 LIVE/TEST 입력을 모두 제어합니다. 기존 `settings.html` 주소는 통합 관리자 화면으로 리다이렉트합니다. 오른쪽 스켈레톤과 캐릭터는 동일한 12관절 소스를 받습니다. 테스트 좌표는 브라우저에만 적용하며 FPGA·위치 Backend는 변경하지 않습니다.
